# ADR-017 版本基线与依赖升级策略

- 状态：草案（Proposed）｜评审：lan、px｜随 PR 合并 main 后转「已采纳（Accepted）」
- 日期：2026-09-18｜决策人：wmj（技术负责人）
- 依据：技术设计v0.1-选型分析.md §4.20、§5；CONTRIBUTING.md §13、§14；仓库 frontend/ 现状

## 背景

新项目重新定版、不照搬旧项目历史锁定（旧项目 NestJS 11.2.3 等锁定属历史原因）。生产依赖必须可复现、可审计、可回滚，且升级有明确流程。

## 决策

**版本基线（阶段 0 完成兼容性验证后锁定精确版本）**：

| 组件 | 基线 | 备注 |
|---|---|---|
| Node.js | 24.x | engines 与 CI 固定 |
| 后端框架 | NestJS 12.x | 阶段 0 兼容性 PoC 后锁定（ADR-003） |
| PostgreSQL | 18.x（精确补丁） | 部署时锁定 |
| React / Vite / Tailwind | 19.x / 8.x / 4.x | 与仓库现状一致（frontend 实测 19.3 / 8.3 / 4.3） |
| TypeScript | 严格模式 | 前端现状 7.0.x；后端兼容版本随 NestJS 12 评估（见下方待复核） |
| Zod / OpenAPI | 4.x / 3.1 | 契约唯一真相（Code-first） |
| Drizzle ORM | 阶段 0 评估最新稳定（含 1.x GA 状态） | 不受旧项目 0.45.x 锁定约束 |
| Nginx | 1.30.x | 生产锁定补丁与 digest |
| MinIO / LibreOffice / ECharts / dnd-kit 等 | 锁定具体版本 + 镜像 digest | 纳入构建门禁 |

**依赖与升级规则（继承 CONTRIBUTING §13 / §14）**：

- 依赖清单 / 锁文件 / CI 与生产构建锁定经过批准的实际版本；禁止 latest / next / beta / rc 进入生产；
- 修改依赖清单必须同步提交锁文件；不得手工编辑锁文件；
- 依赖升级只走独立 PR + 人工确认，不得夹带在功能 PR 中；
- **主版本升级必须新增 ADR 并跑完整回归**；
- 生成物（契约客户端等）只能由工具生成、禁止手改；源与生成物同一 PR 落地并通过无漂移检查。

**待复核差异（不静默选择，评审确认后回写《技术设计v0.1》）**：

1. TypeScript 版本：v0.1 §4.20 表写「5.9.x」，但 §0.1 / §4.9 与仓库现状（frontend 实际 7.0.2）为 7.x——疑为旧稿残留；建议以前端实际 7.x 为基线，后端 NestJS 12 的 TS 兼容版本在阶段 0 一并定案；
2. 包管理器：v0.1 §4.20 写「pnpm 11.x」，仓库现状为 **npm**（frontend/package-lock.json，CI 使用 npm ci）；是否引入 pnpm workspace 属 v0.1 Q15 未定案事项——Q15 定案前，仓库继续以 npm + package-lock 为准。

**阶段 0 实测记录（g4，2026-09-18）**：

- 后端 TypeScript：npm registry 实测 `@nestjs/cli@12.0.3` 依赖 `typescript ~6.0.2`，官方脚手架 `typescript-starter` 为 `typescript ^6.0.2` → 建议后端基线 **6.0.x**（前端维持 7.0.x，`shared/` 构建维持 5.9.x）；待 lan / px 复核后回写《技术设计v0.1》§4.20 定案。
- 包管理器：g4 以 **npm + package-lock** 落地（server/ 已按此实现）；Q15 定案前维持现状。
- 其他实测：NestJS 12 为 ESM 包（`@nestjs/core@12.0.3` 的 `type: module`）→ 后端按 ESM（TS NodeNext）落地；Drizzle ORM 最新稳定仍为 **0.45.2**（1.x 处于 rc，未 GA），g4 采用 0.45.2。
## 备选与不采用原因

不采用「浮动最新版」策略：生产不可复现、升级不可审计、回滚无依据。

## 影响与后果

- 本 ADR 的版本基线是升级与兼容性验证的唯一依据；任何偏离需新增 ADR。
- 阶段 0 的兼容性矩阵验证（NestJS 12 + TS 版本 + Drizzle）结果回写本 ADR。
- 上述两条待复核差异需在 g1 评审（lan / px）时定案，随后同步修正技术设计v0.1 与 CI 配置。

## 切换触发条件

主版本升级、更换基础设施或包管理器决策（Q15）落地时，新增 / 升级 ADR 并跑完整回归。
