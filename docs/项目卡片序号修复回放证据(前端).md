# Push 188 十追订 回放证据（前端：项目卡片「编号 bug」—— 三位数序号被卡片右缘裁掉）

> 业务口径：px 2026-09-24「**这个编号bug**」（截图：项目空间卡片右上角的序号 `204` 末位被卡片右边缘切掉一块）。
> 现象：序号 ≥100 的卡片（演示数据已到 204）右上角编号显示不全，末位被裁。
> 根因（真机探针实测）：序号 `<p>` 原来锚在装饰圆点的**左侧**（`absolute bottom-5 left-6`）—— 两位数时文本框右缘落在卡片右缘内 3px（刚好不裁），三位数宽 42px → 右缘 = **卡片右缘 + 6px**；卡片本身是 `overflow: hidden`，多出来的 6px 连同末位一起被裁。
> 修法：改成 `absolute bottom-5 right-6 whitespace-nowrap` —— 数字**右缘固定、位数变多时往左长**（修后实测恒在卡片内 4px），三位数 / 四位数都不会再越界。改动 1 行 + 一句注释，样式类零新增。

## 编号怎么验的（不是看截图就算数）

- **对账对的是库**：逐张卡读 `<h1>`（项目编号 `code`）→ 查库内 `projects.seq_no`，再比卡面序号文本与 `title` —— 三样对不上就红；卡片张数也与库内未删项目数（108）对齐，不是拿截图数格子。
- **越界怎么量**：`getBoundingClientRect()` 分别取卡片框与序号文本框，三位数那组要求「序号右缘 ≤ 卡片右缘 - 1px」，两位数那组做对照组同量一次（只有三位数那组单测，才说明测的就是这个 bug）。
- **为什么必须一起验 `overflow-x: hidden`**：卡片是 `overflow: hidden`，越界部分是真看不见（不会溢出到卡片外面还能看到）—— 这条一起断言，才说明「越界 = 被裁」，护栏不是自娱自乐。
- **悬停态也量**：卡片悬停会整体放大（`hover:scale-[1.02]`），放大后同样不许越界 —— 用真实鼠标坐标移到卡片上再量一次。
- **护栏自证（关键）**：把 `Card.tsx` 的锚点临时改回 `left-6` 复跑 → **3 条断言变红**（报 `204 越界 6px / 203 越界 6px / 202 越界 6px`、`右越界 85 张` = 库内三位数序号数）；改回 `right-6` 复原后 9 项全绿。说明这条护栏真抓得住这个 bug。
- **顺带坐实一条旧断言**：第 ⑥ 条的文案写着「序号左右都在卡片内」却只查了左缘 —— 这轮补上右缘判定（右越界 85 张就是它报出来的）。
