# ADR-033 企微消息通道改由智能机器人（aibot）承接（群播报 + 单聊 · 应用消息保留备用）

- 状态：草案（Proposed）｜评审：wmj（复核）、px｜随 PR 合并 main 后转「已采纳（Accepted）」｜本件由 lan 代 wmj 线起草（2026-10-14 · 代行 P2 定案），请 wmj 复核决策归属与措辞
- 日期：2026-10-14｜决策人：wmj（技术负责人 · lan 代行定案登记）
- 依据：`docs/M5-03-单聊改智能机器人执行计划(企微单聊).md`（唯一执行口径 · D1 ~ D6 / P1 ~ P3 定案）；`docs/M5-03-实施方案(企微通道).md`（§四 / §五 5.3A / §九）；`docs/PoC-2-回放证据(企微通道).md`；`docs/M5-03-外部依赖清单(企微通道).md`；先例 `docs/adr/ADR-030-Office预览改由ONLYOFFICE承接.md`

## 背景

一期消息通道原口径（ADR-009）：企微自建应用消息（个人提醒）+ 群机器人 Webhook（群播报）+ 站内信兜底。2026-10 演进为智能机器人（aibot）形态：

- **群侧（已落地 · 2026-10-12 ~ 13）**：群通道定案（2026-10-12 · lan 代记 wmj）「群机器人 webhook → 智能机器人 + `chatid`」——Spike 结论：群回调稳定携带 `chatid`、846607 双语义拆清（未激活 / 超频）、限速实测 ≈ 30 条 / 分钟 / 会话（保守口径 = 按会话 30 条 / 分钟 · 1000 条 / 小时）、断连重连正常、激活前置 = 群内发过消息；M5-03-2 ~ M5-03-4 落地并收口（2026-10-13）——群通道（群播报 + 管理员告警出口）全链路真机闭环。
- **单聊侧（2026-10-13 项目组决定）**：单聊推送改走智能机器人（aibot 长连接）；**保留自建应用（`wecom_app`）实现作未启用备用通道**；接受「每个单聊先激活一次」成本。
- **关键实测（决定本决策形态）**：仅 enter_chat 不算激活（推送返 846607），用户发过消息后推送 errcode=0；单聊主动推送帧形（探针 send1）= `chatid` 填 userid + `chat_type` 1 + `msgtype` markdown（官方语义复核 + stub 锁帧 = 实现段首项）。
- **硬约束**：846607 双语义且 errmsg 不可区分 —— 须以激活态 + 本地限速分流；凭据（`WECOM_BOT_ID / SECRET`）只经 env / 仓外演练文件，不入库 / 日志 / 文档。

## 决策

**总**：企微外发（群播报 + 单聊提醒）统一由智能机器人（aibot 长连接）承接；自建应用消息（`wecom_app`）保留为未启用备用通道。

具体条款（转写自执行计划 D1 ~ D6 / P1 ~ P3 定案）：

1. **通道形态（D1 / D2）**：单聊推送主通道改走 aibot；自建应用实现（`NotifyAppService` / `WecomClient` / token 缓存 / app 码表 / `WECOM_APP_*` env / 枚举值 / 路由分支）一律不删，作未启用备用通道。
2. **渠道口径（D5 / P1）**：新增独立渠道值 **`wecom_aibot`** 承载单聊 aibot（不复用 `wecom_app` —— 投递留痕语义与备用通道并存）；群维持 `wecom_group`；模板码一期**保名换渠道**（`R02_WECOM` / `R07_APP` / `A14_APP` / `A01_WECOM_MERGED` 不更名）。
3. **激活语义（单聊）**：激活 = 用户向机器人发过消息（enter_chat 不算 · 实测）；未激活 = **确定性失败**收口（846607 → dead + 同人站内信降级 · 幂等 `:c504`；不回退、不无界重试）；**不做激活表前置拦截**（先发 + 旁证回填，避免表滞后误杀）。
4. **降级指引（P3 · 业务定案 2026-10-14）**：未激活降级站内信**前缀附「如何激活机器人」指引话术**。
5. **回退（D6）**：4 条内置规则渠道值回切 `wecom_app`（纯代码 · 无数据迁移）；群通道路径与告警出口（B2）不动。
6. **与 ADR-009 关系**：本 ADR 承接 ADR-009 之「企微外发渠道形态」部分；站内信兜底、投递语义（Outbox 至少一次 + 幂等 + 限速 + 降级 + 死信 / 连续失败告警）、ChannelAdapter 适配位等其余口径继续有效。

## 备选与不采用原因

- **维持 ADR-009 原形态（应用消息单聊 + 群机器人 Webhook）**：群侧已随 M5-03 切换（定案 + 真机收口）；单聊侧项目组决定改走 aibot —— 不采用；应用消息保留为备用而非主通道。
- **原地修订 ADR-009（不立新 ADR）**：与 ADR 规则 2「决策变更不修改历史结论 —— 新增 ADR，并在旧 ADR 标注被取代」不符；不采用（承接先例 = ADR-030 → ADR-007）。
- **复用 `wecom_app` 枚举值承载单聊 aibot**：投递留痕语义失真、备用通道无法并存 —— 不采用（新增独立值 `wecom_aibot`）。
- **未激活时回退自建应用发送 / 无界重试**：双栈维护成本与重试风暴风险 —— 不采用（D3 确定性失败 + 站内信降级）。
- **激活表前置拦截（未命中不发）**：表滞后会误杀已激活用户 —— 不采用（D4 先发 + 旁证回填）。

## 影响与后果

- **ADR-009 → 部分被本 ADR 取代（Superseded · 2026-10-14）**：仅「企微外发渠道形态」部分；其余口径见决策 6。
- **契约 / 实现**：`NOTIFY_CHANNELS` 增 `wecom_aibot`；4 条内置规则渠道值切换（R02 / R07 / A01 / A14）；`notify_deliveries.channel` CHECK 扩值（迁移 0048 —— 0047 已用于内容译文库）；投递白名单 / outbox 路由新增分支；新增单聊激活表；模板码保名（P1）。
- **运营**：机器人启用范围须覆盖接收人；单聊每人首次激活一次（指引话术进降级站内信前缀 + 依赖清单运营项）。
- **安全**：凭据只经 env / 仓外演练文件；不入库 / 日志 / 文档。
- **回退**：4 条规则渠道值回切 `wecom_app`（纯代码）；群通道路径与告警出口不动。

## 切换触发条件

- aibot 形态不可行（接口下线 / 单聊发送语义变化 / 激活成本不可接受）→ 按回退规则（D6）切回应用消息，并重新评估本决策；
- 其他部门使用不同 IM → 沿用 ADR-009 适配位（ChannelAdapter）启用新通道实现。
