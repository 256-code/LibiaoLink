# ADR-020 流程节点权限：模板仅管理员、项目内增删限项目经理、完成与回退平权

- 状态：草案（Proposed）｜评审：lan、px｜随 PR 合并 main 后转「已采纳（Accepted）」
- 日期：2026-09-20｜决策人：wmj（技术负责人）
- 依据：技术设计v0.3-实施与验收.md §7#2；技术设计v0.2-架构与数据模型.md §4.1 / §4.3；系统功能书.md A1-12 / A1-16 / C3-01 / C3-02；ADR-011、ADR-015

## 背景

ADR-015 曾定「一期节点体系不做权限控制（ADR-011 例外）」，其前提是节点只由蓝图导入生成、用户不可改。业务随后要求项目内可增删节点（模板节点池内、留痕），模板本身则由管理员统一维护（C9-07）；没有权限边界时，任意成员都能改流程结构，门禁与留痕随之失真。本 ADR 明确三档权限，终结该例外。

## 决策

- **模板（蓝图）维护**：保存、发布、导入仅**管理员**（功能权限 admin.blueprint.manage）；项目侧成员对模板只读。
- **项目内节点增删**：仅**项目经理**（项目记录级权限 project.manager，管理员亦可）；增删必须留痕（谁、何时、原因），删除仅限模板节点池（origin 约束不变）。
- **完成与回退平权**：节点的完成（过门禁）与回退（含任务侧完成 / 回退）**项目成员平权**，不额外限权；最终裁决以服务端门禁为准（防绕过），拒绝与留痕口径不变（v0.2 §3.6）。
- **实现方式**：全部走 ADR-011 策略层（记录级权限 + 统一 Guard），不硬编码路由特判；拒绝语义：无功能权限 403、非项目成员按 404（防枚举）。管理员操作同样写审计。
- **变更流程与任务模板的权限**沿用本口径：模板草稿（任务模板页）维护 = 项目经理与管理员，任务创建按模板（A1-16 / A1-17）不改权限结构。

## 备选与不采用原因

- 完全不做权限（ADR-015 原口径）：项目内增删开放给所有人，流程结构不可控，不采用。
- 全部收归管理员：业务要求项目经理在项目内自主增删节点，走管理员会阻塞交付节奏，不采用。
- 引入独立「流程管理员」角色：一期角色数少、收益低，留待需要时再加。

## 影响与后果

- ADR-015 中「一期节点体系不做权限控制」一条口径由本 ADR 修订；M2-05（项目成员与记录级权限）卡片范围覆盖节点增删。
- 节点增删接口（POST /projects/{id}/nodes、DELETE /projects/{id}/nodes/{nodeId}）需补项目经理校验与原因字段（如有）到契约切片（M0-02）。
- 权限矩阵 CI 用例（M1 出口标准）增加：模板维护拒绝（非管理员）、节点增删拒绝（非项目经理）、完成平权允许三类样本。

## 切换触发条件

出现多角色分工（如资料员专责成果文件）或需要按阶段分权时，重新评估角色模型；若节点增删频繁且需要审批，评估并入审批中心（C8，二期）。
