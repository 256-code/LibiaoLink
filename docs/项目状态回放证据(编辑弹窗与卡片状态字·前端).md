## 脚本补丁记录

- **④ 色值对比口径**：Tailwind v4 的 `text-zinc-400` 计算色是 `oklch(0.705 0.015 286.067)`（origin 色空间保留），与 `rgb(161, 161, 170)` 字符串不等 —— 改为「页内造一个 `text-zinc-400` 探针元素，逐卡对比浏览器计算色值」+ 浅灰低饱和语义校验（rgb 通道 ±6 等价 / oklch L 0.6~0.8 且 C ≤ 0.05）。
- **⑰ 控制台口径**：归档门禁的两次故意 422（缺项 422 是业务路径，不是异常）在 Chrome 网络日志里各留一条 `Failed to load resource: … 422` —— 断言改为只豁免「URL 含 `/archive` 的 422 网络日志」，其余 API 报错 / `Runtime.exceptionThrown` / `console.error` 仍零容忍（本轮豁免 2 条）。
- **⑲ 顺序 / 无吸顶断言强化（追订三轮）**：`sidebarExpr` 增加两项探针 —— 「侧栏滚动视口内六个标题的文档顺序」（`heads`）与「视口全子树计算样式 position = sticky / fixed 的元素数」（`stickyCount`）；⑲ 断言 `heads` = `常用筛选,地区,项目类型,项目经理,项目状态,项目时间` 且 `stickyCount = 0`（run9 全绿）。
- **⑲f 详情残留修复**：清理「重置按钮诊断」临时块时，检查详情里仍引用已删变量 `resetBtnState`（run8 流程中止）—— 详情改为只回 hash / 张数 / 总数；run9 全绿。

## 怎么验的（不是看截图就算数）

- **对账对的是库**：108 张卡片逐张 `data-card-status` 与 `select code, status from projects` 对账（断言 ②）；四档切换每次保存后回查 `projects.status` + `audit_logs`（`changes` 里 `status` 前后值，断言 ⑦⑨⑩）；侧栏四枚 chip 计数与库内各档 count 逐档对账（断言 ⑲）。
- **位置与颜色是量出来的**：`getBoundingClientRect` 断言状态字左缘 ≥ 徽标右缘且垂直中心差 ≤ 8px（同排）；`getComputedStyle` 断言字号 11px 与 `text-zinc-400` 同色（不是按截图目测）。
- **侧栏顺序 / 不吸顶是 DOM 断言的**：六个标题按文档序（常用筛选 → 地区 → 项目类型 → 项目经理 → 项目状态 → 项目时间）逐个比对，且滚动视口全子树无 `position: sticky / fixed`（旧吸顶口径已撤）。
- **归档走的是真实门禁**：抛荒项目先点「已归档」保存 → 真实打到 `POST /projects/{id}/archive`，断言 422 `ARCHIVE_GATE_NOT_PASSED`（面板缺项含「任务未完成」、库内未归档、审计留 failed 行）→ 取消不改库 → 再保存 + 「仍要归档」（`confirm=true`）→ 断言 `status=archived` + `project_archives` 1 行（`acknowledged_missing` 含缺项）+ 审计 succeeded + 卡面「已归档」。
- **只读态是 DOM 断言的**：已归档项目打开编辑弹窗，断言四枚选项 `disabled` 全真、保存按钮禁用且文案「已归档只读」、提示「项目已归档：处于只读保护（ADR-027）…」在场。
- **滚动隔离用真实滚轮事件量**：620px 视口下 —— 卡片外（弹窗左缘 −48px）滚 220px：`window.scrollY` 不变、根 `overflow=hidden`、弹窗滚动区 scrollTop > 0；卡片内滚 180px：页面不动、弹窗内继续滚；弹窗不越界、底栏在视口内（⑳）；关闭后根 overflow 复原、页面滚轮恢复（⑳b）。
- **零残留**：抛荒项目的 follows → tasks → node_requirements → project_nodes → project_stages → project_archives → project_members → project_stakeholders → projects 全 0 行（审计行保留为台账）；目标项目 status 还原 active；临时会话已撤销；首页本地记忆（筛选 / 侧栏开合）清掉。
