# ADR-023 阶段推进：项目经理手动触发 + 服务端门禁 + 缺项明细（不做自动推进）

- 状态：草案（Proposed）｜评审：lan、px｜随 PR 合并 main 后转「已采纳（Accepted）」
- 日期：2026-09-20｜决策人：wmj（技术负责人）
- 依据：技术设计v0.3-实施与验收.md §7#5、§3.3（M2-03）；技术设计v0.2-架构与数据模型.md §2.4 / §3.6；系统功能书.md A1-12

## 背景

九阶段顺序固定（售前规划 → … → 验收），业务要求「当前阶段任务全部完成且成果文件齐全后方可推进」，且推进与回退均要留痕。若做成自动推进，业务无法控制节奏（收尾核对、客户节点确认都在人工手里）；若不做门禁，阶段状态会先于事实漂移。

## 决策

- **推进 = 显式接口调用**：POST /projects/{id}/stages/{key}/advance，仅项目经理（与管理员）可触发；**不做自动推进**，任务全部完成只改变展示（完成度），不移动阶段。
- **服务端门禁（事务内）**：锁阶段行 → 校验该阶段全部任务已完成（基础态 done）且必需成果文件满足（复用 GateService，按 node_requirements 逐 doc_type 统计 files.status 属于 final / changed）→ 阶段置 done、下一阶段置 active、projects.stage_key 前移 → 审计 + 同事务写 outbox；**不部分推进**。
- **失败响应**：422 STAGE_GATE_NOT_PASSED，details 返回缺项明细（未完成任务清单 + 缺件清单 + 节点定位），前端据此展示待办摘要。
- **回退 = 同族接口**（带原因）：仅项目经理；回退只允许相邻上一阶段；当前阶段重置 pending、上一阶段恢复 active、projects.stage_key 回移；无门禁（回退是纠错动作），原因必填并留痕。
- **阶段完成度**为派生值（已完成任务数 ÷ 任务总数），读时计算、不落库；阶段时间字段（推进 / 回退时间与操作人）落 project_stages（v0.2 §11.2 A1-12 口径）。
- **与归档的关系**：验收阶段完成后不自动归档，归档另走 C4-02（ADR-027）。

## 备选与不采用原因

- 自动推进（任务全完成即前移）：业务要求人工确认节奏，且收尾核对无法自动判定，不采用。
- 定时推进 / 批量推进多项目：同上，且会掩盖缺件，不采用。
- 允许任意跳阶段或并行阶段：九阶段顺序固定是业务定档口径，不采用。

## 影响与后果

- 迁移切片：project_stages 增推进 / 回退时间与操作人字段（随 M2-03 卡片）。
- 契约切片：advance / rollback 两个操作（含原因与缺项明细结构）登记 M0-02，随 M2 落地。
- 门禁复用：与节点完成门禁共用 GateService，保证「阶段推进 / 节点完成 / 任务完成」三处判定一致。
- 金标用例：缺件 → 422 含明细；补齐 → 200；回退需原因；并发推进（version 冲突）→ 409。

## 切换触发条件

业务要求自动推进、并行阶段或跳阶段时重新评估；若阶段推进需要审批（C8 二期），改为审批通过后推进。
