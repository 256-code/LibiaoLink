# ADR-029 搜索分词：一期 pg_trgm 双字切分，zhparser 仅作 M7 前 PoC 备选

- 状态：草案（Proposed）·**可修订**（复审时间 = M7 开工前，PoC 结论回写本 ADR 或新增 ADR）｜评审：lan、px
- 日期：2026-09-20｜决策人：wmj（技术负责人）
- 依据：技术设计v0.3-实施与验收.md §7#14、§3.7（M7）；技术设计v0.2-架构与数据模型.md §11.1（search_docs）；系统功能书.md C6-01 ~ C6-04

## 背景

一期全局搜索要求中文分词检索（含编号 / 短词）、按对象类型过滤、结果高亮；分词方案二选一未定：zhparser（SCWS 中文分词扩展）质量好但需自编译、与 PG 版本绑定；pg_trgm 双字切分部署成本为零、对编号 / 短词友好，但语义切分能力弱。搜索落在 M7，M0 阶段只需冻结默认方案与切换成本。

## 决策

- **一期默认 = pg_trgm 双字切分**：扩展随基线迁移启用（PostgreSQL contrib 自带，无第三方编译），对 search_docs 投影的检索列建 GIN trgm 索引；相似度排序与关键词高亮在应用层完成。
- **zhparser 列为质量升级候选**：M7 开工前用真实数据跑小规模对比 PoC（召回率 / 精度 / 延迟三项，样本含编号、短词、长描述）；不达标再切换，达标则维持 pg_trgm。
- **切换成本受控**：分词只影响投影列与索引，检索接口、过滤与排序契约不变（search_docs 单点改造）。
- **短词与编号兜底**：单字查询走前缀匹配避免全表扫描；编号 / 型号类按原文匹配优先。
- **本项按 M0 出口标准标注「可修订」**：PoC 结论落开发日志并在本 ADR 回写（新增记录，不改历史结论）。

## 备选与不采用原因

- 直接上 zhparser：部署与版本绑定风险未经证伪，收益（相对 trgm）未量化，不采用。
- PostgreSQL 全文检索 + 简单切分：中文效果差，不采用。
- 外部搜索引擎（ES / Meilisearch）：一期数据量与需求不支撑额外组件，不采用。

## 影响与后果

- 数据库扩展白名单（ADR-004）增 pg_trgm；迁移需 create extension 权限（migrator 角色或 DBA 预装），随 M7 卡片登记。
- search_docs 投影结构与同事务维护口径（C6-04）不变，仅索引与检索函数按方案落地。
- M7 卡片范围含对比 PoC 与结论回写。

## 切换触发条件

真实数据下召回率 / 精度不满足业务检索预期，或业务要求同义词 / 纠错 / 拼音搜索时，重新评估 zhparser 或外部检索引擎。
