## 汇总

- **21 / 21 项全过**（脚本自清理：任务逐条软删 → 项目软删 → 节点物理删 → 模板软删 → 临时会话撤销，库内零残留）。
- 覆盖到的关键口径：① 「模板」标签的「整套添加」确实走 `POST /projects/{id}/tasks/from-template`（3 条一次落库、顺序 = 模板内顺序、阶段取模板阶段、逐条带 `sourceNodeId`）；
  ② 卡片「已添加 N / 整套添加（N）」与行内「已添加」置灰都由 `sourceNodeId` 派生 —— **硬刷新后仍然成立**（不是内存态），且「任务节点」标签同样认（不再只靠「同阶段同名」）；
  ③ 逐条路径（节点库标签）落库同样带 `sourceNodeId`、描述取节点现值；④ 库内 `task_node_id` 逐条对齐、`node_id` 全 null、位次 0 起稠密。
- 脚本侧踩坑留档：① 同一 hash 的二次 `Page.navigate` 被浏览器当同文档导航 —— SPA 不重挂、「刷新后仍在」会假失败，脚本改为先 `about:blank` 再进项目页（硬刷新）；
  ② `POST /projects/{id}/tasks` 的契约里 `title` 必填（`TaskCreateBodySchema`），逐条路径要带上标题 —— 服务端仍以节点库现值为准覆盖（前端也是这么发的）。
