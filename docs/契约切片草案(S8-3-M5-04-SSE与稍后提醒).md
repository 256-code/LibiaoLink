## 二、提案字段 shape

### 2-1 SSE 实时推送（`GET /api/v1/notifications/stream`）

- **信道形态**：`text/event-stream`；认证 = `SessionGuard`（会话 Cookie —— 同源部署下 `EventSource` 自动携带，只读无 `CsrfGuard`；`技术设计v0.2` §1.1 已把 SSE 定为 api 进程职责）。
- **事件集（提案）**：
  - `event: notification` —— `data` = `Notification`（单条新投递 / 稍后提醒到点重提醒；即该行「进入收件箱」的时刻）。
  - `event: unread` —— `data` = `{ unreadCount }`（角标同步：新投递、标记已读 / 全部已读、稍后提醒置读等改变未读数的时刻；跨端一致性口径）。
  - 心跳 = SSE 注释行（`: ping`，周期落 env）——**不进契约**（无载荷、无事件名）。
- **重连补偿（提案）**：服务端**不承诺补发**（无游标状态）；断线重连后由客户端「等下一次事件 + 立即用现有读面补拉」（`GET /notifications` 按 `from` 边界 + `NotificationListResponse.unreadCount`）对齐。`Last-Event-ID` 补发留二期（需新增单调投递序与事件缓冲）。丢事件不产生错误状态：读面永远是真源。
- **连接管理**：每用户最大并发连接数（env，缺省 3；超出拒新连接——策略见 §三-4）；心跳间隔（env，缺省 25s）；服务优雅关闭时先发注释行告知（客户端自动重连）。
- **多实例广播（实现口径预告，见 §三-5）**：投递 / 状态变更在事务内 `pg_notify`（worker 或 api 均可能为写方），api 各实例 `LISTEN` 后桥到本地连接 —— 与 ADR-005「PG 原生队列」同库先例；单实例部署可退化为轮询（env 兼容位）。

### 2-2 稍后提醒（C5-05）

- **`Notification` 扩字段**：`snoozeUntil`（date-time \| null）—— 当前未触发的稍后提醒时刻；`null` = 未设置 / 已触发 / 已取消。触发不改写 `deliveredAt`（首投时刻留档）；重提醒时刻在记录里。
- **`NotificationSnoozeBody`**：`{ snoozeUntil: date-time }` —— 绝对时刻（预设枚举留给前端换算；服务端校验范围：> now + 最短提前量（常量，缺省 5 分钟）且 ≤ now + 30 天）。
- **`NotificationSnoozeRecord`**：`{ id, setAt, snoozeUntil, triggeredAt | null, cancelledAt | null }` —— 「设置与触发记录」读面（C5-05 的「可查」）；一次设置一条，触发 / 取消回填对应时刻。
- **端点（提案）**：
  - `POST /api/v1/notifications/{id}/snooze`（Session + Csrf）→ 返回更新后的 `Notification`（与 `PATCH /{id}` 同款返回）；重复设置 = 覆盖（旧记录标 `cancelledAt` 后写新记录，口径见 §三-6③）。
  - `DELETE /api/v1/notifications/{id}/snooze`（幂等：无未触发稍后提醒也 200）→ 返回更新后的 `Notification`。
  - `GET /api/v1/notifications/{id}/snoozes` → `NotificationSnoozeListResponse`（`{ items }`，按 id 降序，不翻页）。
- **语义（提案）**：设置 = 自动置 `read`（「收下、稍后再看」；角标同步走 `unread` 事件）+ 记设置记录；到点触发 = 该行置回 `unread`（角标 +1）+ 推 `notification` 事件 + 回填 `triggeredAt` + 清 `snoozeUntil`；到点落在免打扰时段 → 顺延到时段结束（复用投递决策先例）；**不消耗每日上限**（用户主动重提醒，非新投递）；对已读 / 已处理行均可设置（用户显式意图优先）。
- **数据面（预告，随实现刀 · 迁移 `0045`）**：`notifications` + `snooze_until`（可空；条件索引）+ 新表 `notification_snoozes`（`notification_id` 级联 / `set_at` / `snooze_until` / `triggered_at` / `cancelled_at`；只加不改，回滚入头注）——高风险 DDL 请 wmj 评审。
- **交互边界**：未投递主行 / 合并子行 / 他人行 = 404（与 `PATCH` 先例一致）；删行随 `notifications` 级联清记录。

## 三、定案记录（wmj · 2026-10-10 · lan 代行登记）

> 定案方式：本稿随 Push 208 / PR #286 提请后，经用户与 wmj 协商，由 lan 代行对十项口径定案并登记（先例 = S8-2 §三「lan 代行审核 / 登记」）。**十项均按原推荐采纳**，无命名 / 字段调整（契约尚未落地，生成物预告维持 §四-1 数字，无二次生成）；契约落地按本记录执行。

1. **SSE 事件集与载荷**：定 **`notification`（单条 `Notification`）+ `unread`（`{ unreadCount }`）**；心跳用注释行（不入契约）；**不设独立 `snooze` 事件名**（重提醒走 `notification`，设置 / 取消走 `unread`）。
2. **SSE 端点入生成物形态**：定 **入 `paths` / `operations`（+1 / +1）**；事件载荷 schema **不入生成物**（先例 `NotifyMessagePayload`）。若生成器技术上无法表达 `text/event-stream` 响应，按备选口径（不进生成物）处理并在落地 PR 登记 —— 其余口径不变。
3. **重连补偿**：定 **「不补发 + 客户端读面补拉」**（服务端零状态）；`Last-Event-ID` 补发 **列为二期**。
4. **连接管理数值**：定 **每用户连接上限 3（env 可调；超出拒新）**、**心跳间隔 25s（env）**；空闲超时随反向代理配置（运维侧）；连接数按日志口径可观测。
5. **多实例广播**：定 **PG `LISTEN/NOTIFY`**（通道名 `notify_stream`；事务内 `pg_notify`）为主案；**轮询兜底保留为 env 兼容位**（`NOTIFY_STREAM_POLL_MS`，弱实时、默认关闭）；单 / 多实例部署均按此实现（多实例零额外配置）。
6. **稍后提醒语义**：定 ① **重投原行**（不生成新消息）；② **设置时自动置 `read`**；③ **重复设置 = 覆盖**（旧记录标 `cancelledAt` + 写新记录）；④ **触发时 `handled` 行照提醒**；⑤ **到点走免打扰顺延、不消耗每日上限**。
7. **读面扩项**：定 **一期不加 snooze 过滤**（M5-07 联调缺再加）；字段名 **`Notification.snoozeUntil`** 确认（语义 = 未触发的稍后提醒时刻；`null` = 未设置 / 已触发 / 已取消）。
8. **范围校验常量**：定 **最短提前量 5 分钟 / 最长 30 天**；毫秒位截断（向下取整到秒）后再做范围校验。
9. **编号与档位**：定 **`S8-3`**（B 案后首个顺延号；`S8-2` 已被 ONLYOFFICE 占用）—— 编号确认，不另安排。
10. **留痕口径**：定 **本切片不写审计**（个人资源先例；`notification_snoozes` 即留痕）；**SSE 连接不写审计**（只读流）。

> 另：十项为最终口径，无补充答复项；契约落地（wmj 线）与实现刀（`M5-04-1` / `M5-04-2` · lan）按本记录执行。
