## 五、失败模型与处置框架（设计基准）

### 5.1 三层级（先分清「没发出」与「发送失败」）

1. **产出前跳过（引擎层）**：`project.group` 未绑定 → `recipient_missing`；责任人缺省失败、事件过期等 —— 不产生消息，需可见性（日志 / 指标），不算投递失败。
2. **投递时发送失败**：企微 API 返回错误 / 网络异常 —— 本框架主体。
3. **发送后语义（一期不做）**：API 受理成功 ≠ 已读；企微发送接口**无幂等键** —— 超时重试可能造成重复（at-least-once），属接受边界、需在设计里写明。

### 5.2 wecom_app 失败场景

| 分类 | 场景示例 | 处置 |
|---|---|---|
| 配置 / 凭据（永久） | Secret / CorpID / AgentId 错（40001 / 40013 一类）；出口 IP 不在白名单；应用停用 | dead + 降级 + 告警（部署问题） |
| token（可恢复） | access_token 过期 / 失效（42001 / 40014 一类） | 刷新后重试一次 |
| 接收人（永久） | userid 不存在 / 离职 / 未激活 / 不在可见范围（60011 一类） | dead + 降级 + 留痕 |
| 频率 / 配额 | 接口频率上限、日配额（45009 一类） | **排队下一窗口，不消耗重试次数** |
| 网络 / 服务端（暂时） | 超时 / 连接失败 / 5xx / 系统繁忙（-1） | 退避重试（有界） |
| 内容（确定） | 内容超字节上限（45002 一类） | 投递层按企微字节上限截断留痕（尾部省略 · **B5 定案**）+ 超上限兜底拒绝 |

### 5.3 wecom_group 失败场景

| 分类 | 场景示例 | 处置 |
|---|---|---|
| webhook 失效（永久） | key 重置 / 机器人被移出群 / 群解散或换群（93000 一类） | dead + 绑定标记 / 告警；降级 = 项目经理站内信 + 管理员告警群留痕（**B4 定案**） |
| 限速 | 单机器人 20 条/分钟（同群多规则叠加最易触发） | 排队顺延；C2-10「按队列限速发送」 |
| 内容超长 | webhook 文本字节上限（2KB 级；A02 长列表必触发） | 投递层截断留痕（尾部省略 · **B5 定案**） |
| 网络 / 服务端 | 超时 / 5xx | 退避重试 |

> 错误码具体值以官方文档 + M5-03-4 真机实测最终锁定（应用消息与 webhook 的错误码集合不同）；锁定后固化为错误分类常量与分支（`M5-03-1` 产出）；**智能机器人（群通道 · P5 定案）错误码已在 Spike 实测（见 5.3A）**。

### 5.3A 智能机器人（群通道 · P5 定案 · Spike 实测 2026-10-10 ~ 10-12）

> 结论：**采纳 —— P5 已定案（2026-10-12 · 均按建议 · PR #309 评论 · lan 代记 wmj）**。验证方法 = 长连接探针（订阅 + 回调抓帧 + `aibot_send_msg`）；原始帧含会话标识，不入库（本节为结论摘要，证据留存于密钥渠道外置环境）。

| 场景 | 实测事实 | 处置建议 |
|---|---|---|
| 会话寻址 | 群聊回调 `body.chatid`（仅群聊返回）+ `chattype`；跨发送者、多次消息 `chatid` 稳定；`aibot_send_msg`（`chat_type=2`）直发成功，不填 `chat_type` 走兼容模式同样成功 | 群绑定键 = `chatid`；业务寻址键仍 `projectId`（S8-1 定案不变） |
| 激活前置 | **需要「用户在会话中发过消息」**才能主动推送；仅 `enter_chat` / 仅进群不算（实测：两人仅进入单聊 → 846607；其中一人发消息后再推 → 成功） | 接入口径 = 每群「机器人进群 + 群内激活一次」；实现侧维护「会话已激活」状态位 |
| 频率限制（846607 语义一） | 60 条 / 0.5s 连发：前 34 条成功，**第 35 条起连续 846607**（文案 `aibot send msg frequency limit exceeded`）；首败后约 4 分钟再发成功 | `rate_limited`：延期重排（不消耗重试次数）；按会话限速桶（30 条/分钟、1000 条/小时，保守值） |
| 未激活（846607 语义二） | 未激活会话推送同样返回 846607，且 errmsg 与超频一致（**不可用文案区分**） | 未激活 → 不重试（准 `permanent`，激活后可发）+ 降级（B4 口径）+ 留痕 |
| 连接 / 订阅 | `853000` = bot_id / secret 无效（订阅回执实测复现）；`846601` = 未开长连接模式（文档码，未复现）；`846609` = 未订阅（文档码，未复现）；断连重连（重新订阅）后发送正常；心跳 30s 正常 | 853000 / 846601 → `permanent`（配置 / 部署类）；846609 → `retryable`（连接恢复重试） |
| 幂等 / 重复 | 同一 `req_id` 重复主动推送、重复回复、延迟约 3.5 分钟回复，均 `errcode=0`（846604 / 846605 / 846606 未触发） | 主动推送不依赖服务端幂等；幂等继续由 Outbox / `notify_deliveries` 保证 |
| 内容上限 | markdown ≤ 20480 字节（官方口径，显著高于 webhook 4096 字节级） | 截断口径沿用 B5（4000 字符 + 投递层按字节截断留痕） |
| 待补 | 机器人被移出群 / 重拉后 `chatid` 是否变化（未做）；`chatid` 失效语义暂按 dead + 绑定标记 + 告警（降级同 B4） | M5-03-4 真机前补测 |

> 定案结果 = **切换**（2026-10-12）；5.3 webhook 口径保留为历史对照。

### 5.4 处置三分类（M5-03-1 实现）

- `permanent` → dead + 降级（C5-04）+ 留痕 + 告警；`retryable` → 退避重试（到顶转 dead + 降级）；`rate_limited` → 延期重排（不消耗重试）；token 失效特例 → 刷新重取一次。
- 留痕：`notify_deliveries`（每次尝试结果 / 状态）—— C2-07 与 C5-03 共用。
- 告警：死信 / 积压沿用 outbox 告警（单条死信即时报）；M5-03-3 起换企微告警群出口。
- 边界：不做已读回执；at-least-once（超时重试可能重复，靠本地幂等键 + 窗口去重压低概率）；「发送成功 = API 受理成功」。

## 六、术语：管理员告警群（B2）

- 定义：给运维 / 管理员看的企微内部群（非业务项目群），接收系统告警：outbox 死信 / 积压 / 最老待领取超龄（`OutboxAlertSink` 现状），后续加企微发送失败率 / 限速触发等（v0.3 §4.10）。
- 成员：一期 = px / wmj / lan，必要时公司 IT 管理员；告警路由按 `团队分工.md` §7。
- 接线：原方案 = 群内添加群机器人 → webhook（等同凭据，只走密钥渠道，不进 Git）→ M5-03-3 落 `OUTBOX_ALERT_WECOM_WEBHOOK`；**定案（2026-10-12 · P5）** = 告警群接入智能机器人（机器人进群 + 群内激活一次）→ `chatid`，env 名随 M5-03-3 定（候选 `OUTBOX_ALERT_WECOM_CHATID`）。
- 注意：告警群自身受限速（原方案 webhook 20 条/分钟；定案后为智能机器人 30 条/分钟 · 按会话）—— 需抑制 / 合并防告警风暴；企微出口失败时回退结构化日志，防告警链自断。
