## 二、提案字段 shape

### 2-1 群播报载荷（新主题 `notify.group`）

- `projectId`：uuid —— 群播报目标项目；**投递层按「投递时读」解析当前群绑定**（换绑后未投递消息仍可送出；未绑定 = 确定性失败，口径见 §三-6）。
- `title`：1 ~ 200 字符（同 `Notification` 先例上限）。
- `body`：1 ~ 4000 字符（同先例）；投递层按企微 markdown 上限（4096 字节）截断并留痕（口径见 §三-5）。
- `refType` / `refId`：成对可空（project / report / task 等，与审计对象类型同词汇表）。
- `templateCode`：可空（逐字模板码：`R03_GROUP` / `R04_GROUP` / `R05_GROUP` / `R06_GROUP` / `A02_GROUP`）。
- **不放 webhook**（凭证不进载荷 / 日志 / outbox 行）；**不放 `mergeKey`**（群播报逐条播报，幂等由 outbox `dedupeKey` 承担 —— 引擎侧已定 `A02:<项目 id>:<日期>` 等）。
- 备选：`groupId`（绑定行 id）替代 `projectId` —— 见 §三-2。

### 2-2 项目群绑定

- `ProjectGroupBinding`：`projectId`（uuid）· `bound`（boolean，false = 未绑定）· `name`（string | null，维护用群名 / 备注）· `webhookMasked`（string | null，**掩码**，只回末 4 位）· `updatedAt`（date-time | null）。
- `ProjectGroupPutBody`：`webhookUrl`（string，企微群机器人 URL 形态校验）+ `name?`（string，可选）。
- 语义：`GET` 恒 200（未绑定 = `bound: false`；项目不存在 / 不可见 404）；`PUT` = upsert（绑定 / 换绑，覆盖语义）；`DELETE` = 解绑（幂等，返回 `bound: false`）。
- 权限：提案 `project.update`（项目主数据维护档）；若 wmj 认为凭证维护要更严，可改提新键 `project.group.manage`（则 `PERMISSION_KEYS` +1、矩阵种子同步）。
- 备选：不落端点、一期仅落库 + 人工 SQL（PoC 够用，但 M5-07 无维护入口）——不建议。

## 三、请 wmj 定案的口径项（评审答复位）

1. **群寻址：独立主题 vs 扩载荷**。推荐 **A：独立主题 `notify.group`** —— 个人消息（`notify.message` → `notifications` 收件箱：合并 / 免打扰 / 每日上限）与群播报（→ 投递记录：限速 / 逐条）的语义、留档与幂等面完全不同；混用会把 `recipientId` 变成判别联合，存量消费方（S7-4 投递内核 / 接线段）全部要跟改。B 备选 = `NotifyMessagePayload` 加 `targetKind` + `recipientId` 放开（改动大）。
2. **群消息寻址键：`projectId`（推荐）vs `groupId`**。一期一项目一群、引擎主体即项目（`project_day` / 任务主体随项目），`projectId` 最稳（换绑后仍可投）；`groupId` 留给二期多群（部门群 / 多机器人）。
3. **群绑定写入口归属**：项目嵌套子资源（`/projects/{id}/group`，推荐；先例 `/projects/{id}/archive`）vs 独立资源 —— project 领域归属 wmj，本提案含 `GET | PUT | DELETE` 三条。
4. **webhook 读取口径**：只写不读（读面回 `webhookMasked` 掩码，推荐）vs 管理员可回读完整值。凭证应最小暴露；完整值仅落库 + 企微后台可查。
5. **超长口径**：`body` 上限 4000 字符（同通知先例）+ 投递层按企微字节上限截断留痕（推荐）vs 产出侧保证不超长（A02 汇总长列表场景不现实）。截断策略（尾部省略 / 保留条目数）请评审一并定。
6. **群失败降级目标（业务口径）**：C5-04「企微失败 → 站内信保底」对**个人消息**天然成立（收件箱行已在、置可见即可）；**群消息**失败降级给谁（项目经理站内信？管理员告警群？）—— 本切片不阻塞（先占 `notify_deliveries` 状态位），请 wmj 汇总业务口径后登记。

另有一项**不扩契约**的确认：`Notification` 读面**不加渠道字段**（C5-02 分类按类型；C5-03 全量留档由「发送记录」承担）—— 渠道与投递结果落 `notify_deliveries`（server 数据面，随 M5-03-2 / M5-03-3 迁移）；M5-06 出读面时若前端确需渠道徽标再议。
