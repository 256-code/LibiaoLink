# ADR-026 问题处理时限（SLA）：按归类配置时限、落 due_at、T+1 提醒 / T+3 升级

- 状态：草案（Proposed）｜评审：lan、px｜随 PR 合并 main 后转「已采纳（Accepted）」
- 日期：2026-09-20｜决策人：wmj（技术负责人）
- 依据：技术设计v0.3-实施与验收.md §7#11、§3.6（M6 问题闭环）；技术设计v0.2-架构与数据模型.md §2.4 / §11.1；系统功能书.md A3-14 / A3-17 / C9-01

## 背景

问题四态闭环（未分组 / 未解决 / 处理中 / 已完成）已有定档口径，超期升级要求「T+1 提醒责任人、T+3 升级项目经理（规则 A03）」，但「处理时限」按什么维度和配置一直未定；若不落期限字段，超期只能靠人工判断，统计（响应时长 / 关闭率）也无法计算。

## 决策

- **时限按问题归类配置**：处理时限挂在问题归类字典的元数据（如 metadata.slaHours），随 C9 字典维护；未配置归类的默认时限取字典级默认值（种子给出，M0-03）。
- **落 due_at 字段**：issue 创建时按归类时限计算 due_at 并落库（created_at + 时限，自然日 / 小时口径以字典粒度为准）；改归类时按新归类重算 due_at 并留痕。
- **提醒与升级**：A03 每日 09:00（Asia/Shanghai）扫描——超过 due_at 1 天提醒责任人（T+1）；超过 3 天升级项目经理（T+3）；已完成的问题不再提醒（闭环即止）。
- **逾期口径**：due_at 早于当前时刻且状态非已完成 = 逾期；逾期标签与统计（响应时长、关闭率）以此为唯一来源，不再另行本地计算。
- **日历顺延**：提醒发送窗口的节假日顺延按 D5-02 配置执行；due_at 本身按自然日计算（一期不吃工作日历，避免期限随节假日漂移）。
- **状态与时限的边界**：due_at 只约束「处理时限」，不改变四态流转；「超时未确认自动关闭」（规则 A04）仍按 Q28 业务确认后补充，不在本 ADR 范围。

## 备选与不采用原因

- 全局固定时限：不同归类（机械部 / 供应商原因 / 客户原因等）时限需求不同，不采用。
- 不落 due_at、实时计算：无法索引、无法统计，且历史配置变更后口径漂移，不采用。
- 时限按问题逐条手填：维护成本高、口径不齐，不采用。

## 影响与后果

- 迁移切片：issues 增 due_at（随 M6 卡片）；字典 metadata 增 sla 字段（C9 字典契约已就位，属取值扩展）。
- 契约切片（M0-02）：Issue / IssueListItem 增 dueAt 与逾期标记；IssueCreateBody 不暴露 due_at（由服务端算）。
- 规则实现：A03（问题超期升级）落在 M5 / M6 卡片，金标用例覆盖 T+1 / T+3 / 完成即止 / 重跑幂等。
- 统计口径（A3-17）与看板排序依赖 due_at，需在 M6 出口标准中体现。

## 切换触发条件

业务要求按项目 / 干系人 SLA 分级，或接入工时日历（工作日口径）时，重新评估时限来源与 due_at 计算口径。
