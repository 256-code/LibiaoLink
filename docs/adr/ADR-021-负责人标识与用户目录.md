# ADR-021 负责人标识：统一用用户 id 关联 + 显示名随行（待分配可空）

- 状态：草案（Proposed）｜评审：lan、px｜随 PR 合并 main 后转「已采纳（Accepted）」
- 日期：2026-09-20｜决策人：wmj（技术负责人）
- 依据：技术设计v0.3-实施与验收.md §7#3、§3.2（已入契约 A2）；技术设计v0.2-架构与数据模型.md §2.2 / §11.1；系统功能书.md A2-01 / D1-02；前端功能需求.md §三（人员目录）

## 背景

源表与前端原型用「姓名 + 拼音名」承载负责人（前端字段 owner / ownerEn），人员目录是 31 个虚构成员；一旦重名、改名或人员停用，关联与检索都会失真。users 表与用户目录接口（GET /users，A2 · Push 49）已就绪，任务的 owner_id 在 0001 基线即为 uuid 外键形态；但契约 A10 写了「ownerId 缺省 = 项目经理兜底」，与原型「留空 = 待分配」冲突，需要一个统一裁定。

## 决策

- **关联键 = users.id（UUID）**：任务负责人、项目经理、项目成员、关注与通知接收人一律存 id；姓名 / 拼音名只作展示，不参与关联、比较与去重。
- **接口口径**：写接口收 ownerId；读接口下发 ownerId + ownerName（列表 / 详情 / 创建与编辑返回一致）；项目经理为 managerId + managerName 随行（A2 选 b）；不引入独立拼音字段。
- **待分配可空（本 ADR 裁定，修订 A10 的兜底描述）**：任务负责人允许为空，前端显示「待分配」；创建任务时 ownerId 缺省 = 空，**不自动兜底为项目经理**。原 A10「缺省 = 项目经理兜底」随 M0-02 切片表修正（列为待复核差异，见下）。
- **用户目录搜索**：GET /users 的 q 支持姓名 / 拼音 / 岗位（服务端实现，含停用过滤：只返回启用用户）；前端删除本地虚构目录（members.ts 的 31 人）并切到接口。
- **展示与留痕**：审计与业务留痕存 id；姓名变更不回写历史记录；停用用户的在办任务展示原负责人并标注「已停用」（M1 组织同步落）。
- **迁移口径**：tasks.owner_id 由 not null 改可空（待分配）；历史数据导入时按姓名 + 工号建立映射表再落 id（PoC 7 / M8，映射结果人工复核）。

## 备选与不采用原因

- 工号做关联键：工号来自 SSO、存在变更与外部干系人无工号的场景，不采用。
- 姓名直接关联：重名与改名不可控，不采用。
- 保留 owner / ownerEn 双字段并行：双写不同步、排障成本高，且拼音名应由搜索能力承担，不采用。

## 影响与后果

- 契约切片（M0-02）：Task / TaskListItem / TaskCreateBody / TaskUpdateBody 的 ownerId 可空 + ownerName 随行；撤回 A10 的兜底描述；users 目录 q 增拼音口径（M1 实现）。
- 迁移切片：tasks.owner_id 改可空（随 M2 / M3 卡片）；users 增拼音检索支撑（列或函数索引，随 M1）。
- 前端：人员下拉数据源从本地目录切到接口；「待分配」为默认空态（与现状一致）。
- **待复核差异**：本 ADR 与 A10 契约描述（Push 62）不一致处已显式记录，按本 ADR 执行；如业务要求「新建任务必须有人」则改为创建必填（前端默认带出项目经理为初始值，但不落库兜底）。
- 高风险评审范围（契约 + 迁移），合入 main 前需非作者评审（CONTRIBUTING §15）。

## 切换触发条件

外部干系人需要被指派为负责人时，评估「用户 / 干系人」双实体指派模型（stakeholder 台账与 users 不混用）；引入多组织租户时重新评估 id 范围。
