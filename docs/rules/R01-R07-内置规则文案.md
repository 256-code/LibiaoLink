## R01 变更文件自动关联

| 项 | 设计说明（原文） |
|---|---|
| 触发时机 | 变更管理模块新增记录，且「变更时间」非空 |
| 触发条件 | 同时满足：变更文件非空、变更后文件非空、变更后文件版本非空 |
| 执行动作 | 在任务主表中查找满足「输出成果文件非空且输出成果文件 = 新增记录的变更文件」的任务，将其「变更关联」字段写为新增变更记录的记录 ID |
| 关联方式 | 追加关联（一条任务可关联多条变更）并去重；原文未说明追加还是覆盖 → 已定：追加 |
| 异常处理 | 无匹配任务时记录日志并提示申请人；匹配到多条任务时全部关联并在消息中列出 |
| 实现要点 | 「输出成果文件 = 变更记录的变更文件」按「任务输出成果文件值 = 变更记录的变更文件值」理解（多值匹配：变更文件命中任务 deliverable_types 任一取值即算命中） |

- 无消息文案（不发送通知类消息；通知由 A05 等规则承担）。
- 落点：变更生效事务内同事务回写（技术设计v0.3 §3.5 M4-04），随 M3 / M4 卡片实现。
- 金标：多值任务命中全部关联；重复变更不重复关联（幂等）；无匹配 → 日志 + 申请人提示；关联写入与任务版本号（乐观锁）不冲突。

## R02 成果文件自动化通知

| 项 | 设计说明（原文） |
|---|---|
| 触发时机 | 任务主表中记录更新，任务状态变为「已完成」或「提前完成」 |
| 触发条件 | 输出成果文件非空，且「文件」字段为空（任务完成但未上传成果文件） |
| 执行动作 | 向该任务的 任务负责人 发送消息 |
| 消息标题 | 及时添加文件 |
| 消息内容 | 请为项目任务{任务描述}及时添加成果文件 |
| 补充设计 | ①若任务负责人为空则通知项目经理；②发送后若 N 天仍未上传，可再次提醒并升级（见 A15）；③同一任务只提醒一次，上传后自动停止 |

- 渠道：个人提醒（企微单聊 + 站内信，系统功能书 C2-11）；免打扰时段按 C2-09。
- 金标文案（逐字）：标题「及时添加文件」；内容「请为项目任务{任务描述}及时添加成果文件」，{任务描述}取任务 title 原文。
- 金标：负责人为空 → 接收人回退项目经理；同任务重复完成事件只提醒一次；上传文件后停止后续提醒。

## R03 任务即将延期提醒

| 项 | 设计说明（原文） |
|---|---|
| 触发时机 | 预计完成日期前 1 天 08:00（定时任务扫描） |
| 触发条件 | 任务状态不属于「已完成」「提前完成」 |
| 执行动作 | 发送消息到相关群聊（项目群） |
| 消息内容 | hello，{任务负责人}，你的任务{任务描述}还有1天就要截止了，快加加油，尽快追上进度吧！ |
| 补充设计 | 群聊取「项目-群聊」绑定关系；同时可选私信负责人；节假日是否顺延可配置 |

- 无消息标题；内容逐字（含 hello 小写与感叹号）。
- 金标：T-1 命中；已完成 / 提前完成不命中；节假日顺延开 / 关两态各一例；跨天补跑（worker 重启）按应执行清单补发且不重复。

## R04 任务启动提醒

| 项 | 设计说明（原文） |
|---|---|
| 触发时机 | 开始日期当天 10:00 |
| 触发条件 | 原文未设附加条件；建议增加「任务状态为待开始或进行中且未填实际开始日期」以减少无效提醒【待确认】 |
| 执行动作 | 发送消息到相关群聊 |
| 消息标题 | 有新任务已到启动时间 |
| 消息内容 | {任务负责人}你好呀，你的任务{任务描述}已到启动时间，快查看任务详情吧~今日工作加油 |
| 补充设计 | 消息中附带任务详情链接与「开始任务」按钮，可直接开工 |

- 金标：当天 10:00 命中；标题与内容逐字；附链接与按钮（链接为任务详情深链）。
- 待确认：触发条件是否采纳建议（未填实际开始日期 + 状态过滤）。

## R05 任务超时提醒

| 项 | 设计说明（原文） |
|---|---|
| 触发时机 | 预计完成日期后 1 天 08:00 |
| 触发条件 | 任务状态不等于「已完成」（原文口径）；建议统一为不属于「已完成 / 提前完成」，与 R03 保持一致【待确认】 |
| 执行动作 | 发送消息到相关群聊 |
| 消息标题 | ！任务超时提醒 |
| 消息内容 | hello，{任务负责人}，你的任务{任务描述}已经超时一天了，快加加油，尽快追上进度吧！ |
| 补充设计 | 超时后可按 T+1 / T+3 / T+7 逐级提醒并升级到项目经理（见 A03、A06） |

- 金标：T+1 命中；标题逐字（含开头全角感叹号）；已完成不命中；升级链路（T+3 / T+7）与 A03 / A06 组合用例。
- 待确认：条件口径是否与 R03 统一（本库按「不属于已完成 / 提前完成」实现，标记可修订）。

## R06 任务完成喜报

| 项 | 设计说明（原文） |
|---|---|
| 触发时机 | 任务状态变为「已完成」或「提前完成」 |
| 触发条件 | 实际完成日期非空，且项目进度 = 100% |
| 执行动作 | 发送消息到相关群聊 |
| 消息标题 | 叮咚~喜报来啦！ |
| 消息内容 | 恭喜{任务负责人}成功拿下一项重要任务：{任务描述}。大家一起为这位优秀的伙伴喝彩吧 |
| 补充设计 | ①「项目进度 = 100%」按任务所属项目整体进度判定【待确认：也可理解为该任务自身进度】；②可扩展为阶段完成喜报、项目验收喜报；③喜报可生成海报图便于转发 |

- 金标：项目整体进度 100%（最后一格完成）时命中；非 100% 不命中（若业务改为「任务自身进度」则改金标）。
- 待确认：「项目进度 = 100%」判定范围（本库按项目整体进度实现，标记可修订）。

## R07 每周一提醒跟进重要 / 紧急任务

| 项 | 设计说明（原文） |
|---|---|
| 触发时机 | 每周一 09:30 |
| 触发条件 | 任务状态 = 进行中，且紧急重要度属于「重要且紧急 / 紧急但不重要 / 重要但不紧急」 |
| 执行动作 | 对每条符合条件的记录，向其任务负责人发送消息 |
| 消息标题 | 重点任务提醒 |
| 消息内容 | 以下重点任务正在进行中：{任务描述}请关注并及时推进任务~ |
| 补充设计 | 同一负责人当周多条任务时 合并为一条 消息（任务清单形式），避免消息轰炸 |

- 金标：周一 09:30 命中；「不紧急不重要」不命中；同一负责人多条任务合并为一条（清单形式）；跨周窗口幂等（同一周不重复）。
- 合并形态（先行口径 · M5-01 · Push 161）：同一负责人当周多条 → 一条清单式消息（模板码 `R07_APP_MERGED`，正文 = `以下重点任务正在进行中：{任务清单}请关注并及时推进任务~`，`任务清单` = 各任务描述以「、」连接、顺序随输入数据集；单条命中同样走该形态，文案与 `R07_APP` 逐字一致）；幂等键 = 规则 + 收件人 + ISO 周（如 `R07:<负责人 id>:2026-W39`）—— 已由 `server/test/automation-replay.test.ts` 固化为断言。
