# ADR-032 CAD 工程测量：服务端几何内核 + 浏览器展示 + 版本化尺寸依据

- 状态：修订提案（Proposed，2026-10-13）；业务已要求按本方案整理文档，技术选型与契约仍须非作者评审，合并后再转 Accepted。本文不代表功能已经实现。
- 决策人 / CAD 主责：wmj；评审：lan、px。
- 关系：采纳后替代 ADR-031 的三维纯浏览器直读主路线、测量与选型结论，并更新 ADR-008 的实施策略；保留数据不出内网、二维条件性交付、失败可下载原则。
- 依据：业务确认“测量结果作为加工或验收尺寸依据”；公差、主要格式、典型模型规模及预算暂不确定。现有实现基线为 PR #323（main `57a4849`）。
- 执行入口：[CAD 工程测量实施方案与任务](../CAD工程测量实施方案与任务.md)。

## 背景与已确认事实

PR #323 已加入 CadViewer 和三维原对象直签入口，尚不具备工程尺寸依据的完整能力。源码核对发现：小于 1 的长度乘以 1000 后仍标 mm；IGES 进入 ReadStepFile；OBJ/glTF/GLB 只有路由白名单、没有加载实现；零件面板为平面列表；距离来自网格拾取、直径来自共面顶点估算；爆炸效果移动了测量使用的世界坐标。此处为源码结论，未进行样本运行验证。

ADR-031 引用的两份 PoC 报告在本次仓库核对中未找到。97.7% 转换率、样本耗时和视觉表现作为历史记录保留，不能作为本方案的尺寸精度或图纸保真验收证据。

几何值、设计要求和实物检验值需要分开：CAD 几何计算不自动携带公差，更不能证明实际零件合格。本期只交付模型查询、尺寸依据关联及记录追溯；实物采集和自动合格判定不在本期范围。

## 决策

### 1. 三维主路线

采用服务端 OCCT/XDE 导入与几何计算，Three.js 展示和交互。优先验证 C++ 几何进程；具体版本、构建与部署参数在 CAD-1 验证后锁定。NestJS 负责权限、版本、任务和记录；复用现有 Outbox、worker、对象存储，不新增队列基础设施。

导入产物包含：可恢复的几何模型、装配定义与实例树、显示网格/边线、显示元素到 CAD 特征的映射、单位和诊断、版本化清单。几何序列化格式须通过 CAD-1 恢复验证后冻结，不能把三角网格当作原始 B-Rep 存档。

浏览器直读仅作为参考预览的可选降级能力。动态 import 仅延迟加载，不能替代 Web Worker；保留客户端解析时需要任务取消和资源释放。

### 2. 测量定义与不变量

- 首期支持经验证的解析圆/圆柱直径和半径、CAD 顶点距离、平行面间距、定义明确的圆心/轴线距离与直线/平面角度；按特征能力分别开放。
- 任意曲面自由点、拟合圆和纯网格测量默认为参考；不宣称工程精度。
- 前端提交文件版本、导入产物、零件实例及特征标识；服务端从真实归属校验并加载模型，计算时使用原始装配坐标。显示归位、旋转、爆炸和 LOD 不改变工程数值。
- 零件定义与实例分离；相同零件的多个实例保留各自原始变换。特征 ID 只在一个导入产物版本内稳定，不自动跨文件版本或重新导入迁移。
- 保留源单位，内部统一毫米和双精度。未知单位不默认当毫米；经确认的单位配置进入导入标识。显示位数、算法容差和整体误差是不同概念。
- 缺单位、特征不支持、映射失效或几何异常影响计算时，拒绝相关工程测量并说明原因，不静默降级为近似值。

### 3. 尺寸依据

首期优先验证 STEP + 批准图纸路径：几何结果关联图纸文件版本、页码/尺寸编号、名义尺寸、公差和确认人。读取三维标注时区分图形 PMI 与语义 PMI，只有验证过的标注类型及几何关联可参与尺寸依据。

“已关联依据”不等于“实物已合格”。批准身份和确认权限复用项目业务规则，具体角色与撤销流程在 CAD-2 契约评审中确定，不能默认所有预览用户可确认。若实际业务仅提供 PMI 模型，PMI 验证成为工程交付前置条件，不能用缺失的二维图纸兜底。

### 4. 二维通道

继续验证 DWG → LibreDWG → DXF → ezdxf → SVG/PDF，DXF 可直接导入。区分模型空间/布局，保存字体、外参、打印样式和转换诊断；智能视口只改变初始范围，不丢弃原始内容。转换出的 SVG/PDF 是派生产物，设计方批准的原始 PDF 单独标识。

转换成功率不等于保真率；同一渲染器的 SVG/PDF 不能互相证明正确。首期不从画面像素或 OCR 直接生成工程尺寸。若真实图纸的关键实体、布局或字体不满足要求，比较 ODA 完整渲染路线，不能假定仅替换 DWG→DXF 转换就可解决问题。

### 5. 契约、产物与缓存

新增 CAD 专用任务和模型清单，复用调度机制而非把完整模型包塞进现有 pdf/image/structured 三值。当前 preview.job 是单目标/单产物；“一次转换双产物”必须显式实现产物协调，不能仅凭缓存键宣称已支持。

导入键由源内容哈希、依赖摘要、引擎版本、导入配置摘要组成；外部参照、字体/打印样式及单位确认等影响结果的输入必须参与版本化。多产物写入完成后才发布可用清单；显示能力和工程测量能力分别报告。相同内容复用不能替代每次访问时的权限检查。

几何服务无数据库凭据、不直接暴露公网；现有受控服务传入数据。导入任务隔离、限时限资源；热模型内存缓存有上限和淘汰策略。首期不增加新的集群或任务基础设施。

测量计算与保存分开：普通查看及临时计算延续“预览不写操作日志”；主动保存/确认是版本化业务记录，记录真实操作者。历史记录不自动绑定新版本，撤销依据不删除原始记录。删除/归档与记录保留策略在迁移前明确，与现有文件生命周期一致。

## 备选与不采用原因

| 路线 | 结论与取舍 |
|---|---|
| occt-import-js + Three.js 纯客户端 | 保留参考预览；当前封装输出网格，工程几何查询需扩展。不是浏览器不能计算，而是当前交付与资源管理成本较高 |
| OCCT/XDE 服务端 + Three.js | 主验证路线：统一导入参数、复用几何与测量版本；代价是服务端资源、映射和服务开发 |
| CAD Exchanger / HOOPS | 可用同样本作商业对照；几何、PMI 和原生格式能力以具体产品版本为准，价格及离线授权未核实 |
| ODA Drawings / inWEB | 二维候选；浏览器处理 DWG 并非不可行，私有部署也不与内网约束天然冲突 |
| Autodesk APS 等上传第三方云方案 | 继续排除：不符合数据不出内网约束 |

服务端预转换可以生成分件/LOD，再由浏览器按视角加载；不再使用“无法按客户端视锥裁剪”作为排除理由。依赖许可证按实际版本、链接及分发方式核对，不沿用“WASM 动态链接自动没有义务”的笼统结论。

## 影响与后果

- 增加几何服务、派生产物、测量契约及业务记录；现有查看器和文件平台继续复用。
- 先实现一个 STEP 版本、限定测量类型和批准图纸关联的完整链路，再扩大格式和性能范围。
- 首期候选格式不是支持承诺：STEP 为主，IGES 逐项验证；STL/3MF/OBJ/glTF/GLB 仅按实际加载实现开放参考预览；原生 CAD 格式先采用设计端导出路径。
- 未知的公差、样本、硬件、并发和预算列入 CAD-1 输入。未确认前不承诺毫米级误差或固定工期；不以历史转换率替代精度验证。
- 当前代码缺陷仅登记为 CAD-0，本次文档修订不修复运行时问题。工程能力不能因本 ADR 合并就显示为可用。

## 切换触发条件

- OCCT 在代表性样本上无法满足单位、几何或必要 PMI 要求：评估商业内核，不以网格近似补足工程能力。
- 原生专有格式成为主需求：比较设计端导出与 SDK 成本及版本一致性。
- 实测显示内存或首次显示超预算：增加分件加载、LOD 与流式处理，不以文件大小单一阈值决策。
- 二维关键标注缺失：降低该文件能力等级，回到批准原件，并评估替代引擎。

## 待复核差异与状态

旧功能书的“一期仅管理、三维默认二期”是历史排期；PR #323 已加入预览代码，但尚未证明完整格式与工程能力。工程交付按 CAD-0～CAD-5 阶段门禁，不把文档修订当作上线承诺。ADR-031 和 Push 285 中的历史陈述保留，并通过本次更正和任务清单解释差异。
