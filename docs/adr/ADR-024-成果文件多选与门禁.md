# ADR-024 成果文件：任务侧多选 deliverable_types，门禁以 node_requirements 为准

- 状态：草案（Proposed）｜评审：lan、px｜随 PR 合并 main 后转「已采纳（Accepted）」
- 日期：2026-09-20｜决策人：wmj（技术负责人）
- 依据：技术设计v0.3-实施与验收.md §7#6、§3.4（M3-03 关键设计）；技术设计v0.2-架构与数据模型.md §2.3 / §3.6 / §11.2；系统功能书.md A2-10 / A4-20 / C9-01

## 背景

源表「输出成果文件」是十类成果文件字典的多选（CAD图纸 / 技术协议 / 合同 / 评审单 / 设备清单 / 物料总清单 / 发货装箱单 / 到货单 / 安装完成证明 / 验收单）；0001 基线 tasks.deliverable 与现有契约 Task.deliverable 都是单值，与源表和前端多选现状不符。同时门禁必须只有一个判定来源，避免「任务说要有、节点说不用」两套口径。

## 决策

- **任务侧多选**：tasks.deliverable 改为 deliverable_types（数组，取值属于成果文件字典十类，可空、可去重），契约同步为 deliverableTypes: DocType[]（Task / TaskListItem / TaskCreateBody / TaskUpdateBody 一致）；迁移为存量单值转单元素数组（迁移切片，随 M3）。
- **门禁唯一来源 = node_requirements**：任务完成与节点完成都按所属节点的 required_doc 逐类统计 files.status 属于 final / changed；任务自身 deliverable_types 不构成独立门禁，只作为「应产出什么」的展示、R02 提醒条件与快筛（未上传成果文件）输入。
- **无节点任务的兜底**：直连项目的任务（node_id 为空）按自身 deliverable_types 判定——要求了类型就必须有对应文件（同一 GateService 的兜底分支）。
- **未定档放行 + 提醒**：存在 draft 文件时门禁放行并返回 warning，同时触发 R02（与 v0.3 §3.4 口径一致）；拒绝一律 422 + 缺件明细（A4-20）。
- **锁定口径**：deliverable_types 随模板节点生成后默认锁定（A1-17），管理员修正需原因留痕（M3-05）。
- **字典口径**：十类取值由 C9 字典唯一维护；增删类型属于字典变更（C9-02），门禁引用同步校验（DICT_VALUE_UNKNOWN）。

## 备选与不采用原因

- 维持单值：与源表、原型和业务多选现状冲突，不采用。
- 任务侧也做独立门禁：两条来源必然出现判定分歧与排障成本，不采用。
- 允许自由文本类型：门禁无法引用、统计失真，不采用。

## 影响与后果

- 契约切片（M0-02）：Task 族 deliverable 改 deliverableTypes（数组）；错误码复用 TASK_REQUIRED_DOC_MISSING / CHANGE_FILE_REQUIRED。
- 迁移切片：tasks.deliverable_types text[]（含存量转换与 CHECK / 索引评估），随 M3 卡片。
- 字段对照清单与前端表格「输出成果文件」列改多值展示（前端侧随 M3-07 联调）。
- 与 ADR-019 蓝图约束、ADR-023 阶段推进共用 GateService，保持三处一致。
- **R01 变更关联的匹配与派生读（M4-04 落地口径，v0.2 §5.3 / v0.3 §3.5）**：现按 `tasks.deliverable` **单值等值**实现（写面 `tasks.change_ref` 回写 + 读面派生任务关联）；**本 ADR 迁移切片落地时同批改为多值命中** —— 变更文件 `doc_type` 属于 `deliverable_types` 任一取值即命中，写面与读面两处同步改，避免迁移后 R01 静默失配。
- **已落地（M3-03 · Push 143）**：迁移 `0018_task_deliverable_types.sql`（`deliverable` 单值 → `deliverable_types` text[] 非空默认空数组、存量转单元素数组、双 CHECK + GIN）；契约 `deliverableTypes` + `GET /projects/{id}/tasks/{taskId}/can-complete` / `POST …/complete`（422 `TASK_REQUIRED_DOC_MISSING` / 409 `TASK_ALREADY_DONE`）；门禁实现 = 有节点任务按所属节点 `node_requirements`、无节点任务按自身 `deliverable_types` 兜底（每类 ≥ 1 份），draft 放行 + R02（`task.draft_doc_reminded`）。余项：R01 多值命中随 M4-04 切片（#111）并入同批改；模板锁定例外调整随 M3-05。

## 切换触发条件

成果文件类型需要按项目类型细分（类型专属字典）或需要多版本并用时，评估字典分域；若业务要求任务级强制门禁，则在 node_requirements 之外新增任务级约束类型而不是复用本字段。
