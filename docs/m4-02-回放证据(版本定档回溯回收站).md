## 验收对照（M4-02）

- 读面 = L2 / L11：`GET /files/{id}`（含当前版本）与 `GET /files/{id}/versions`（版本链，按 seq 升序）；读面项目可见即可，非成员 404。
- 定档锁版 = L3：draft → final，`finalized_at/by` 成对落库，审计 action=complete + outbox `file.finalized`。
- 并发定档 409（M4 出口标准）= L10：两个请求持同一 version，恰好一个成功、一个 409 VERSION_CONFLICT。
- 定档后管控 = L4 / L5：对已定档文件追加版本 409 FILE_STATE_INVALID；定档后回溯 = 变更（M4-04 申请即通过：change_requests + 新版本挂 change_request_id + 状态 changed）。
- draft 追加版本（Push 130 定案放开）= L6 / L7：`intent=version + fileId` 同一文件行追加 v2；名称 / 跨项目不一致 400。
- 回溯 = L8 / L9：复制目标版对象到新版本契约键、生成新版本（不删历史）；目标即当前版本 400 already_current。
- 回收站 = L12 / L13：任意状态可删（记 `recycled_from_status`、`purge_after = +30 天`）；恢复回到进入前状态。
- 到期清理任务 = L16：worker 启动即跑一轮 —— 过期文件按版本清对象 + 删元数据 + system 留痕（actorId=null）。
- 彻底删除 = L14 / L15：仅系统管理员（成员 403）；非回收站 409；对象与元数据一并清、留痕（deletedVersions）。
- 单测回归（不连库）：server/test/file-service.test.ts（55 例）随 npm test 常跑：定档 / 并发 409 / 无版本 400 / 回溯（复制对象 + already_current + 位次竞态）/ 回收与恢复 / 越权 403 / 到期清理与跳过。
