# ADR-006 对象存储：S3 协议抽象 + MinIO 单节点（自建）

- 状态：草案（Proposed）｜评审：lan、px｜随 PR 合并 main 后转「已采纳（Accepted）」
- 日期：2026-09-18｜决策人：wmj（技术负责人）
- 依据：技术设计v0.1-选型分析.md §0.1、§4.6、§4.17、§5（#7）

## 背景

文件是本项目最重的一类资产：图纸与三维文件常见几百 MB，需要预签名直传、分片与断点续传、版本控制、生命周期与异地备份；同时「不允许上传第三方云」是业务硬约束。

## 决策

- **接口层**：全部代码只依赖 S3 协议接口，封装在文件 / 存储模块内，实现可替换。
- **一期实现**：MinIO 单节点 + 独立数据盘 + 桶版本控制 + 每日增量异地同步 + 定期抽检恢复。
- **工程要点**：
  - 浏览器经 api 申请预签名 URL 直传，api 不代理大文件流量；
  - 预签名 URL 的 host 必须对客户端可达（外网 / 内网两种部署形态在阶段 0 用真实网络验证）；
  - 对象键 = 项目 / 任务 / 版本 / 哈希，内容哈希去重，原文件名（含中文）存元数据；
  - 「定档」在数据库层锁版，物理层不覆盖；
  - 草稿 / 临时文件 30 天生命周期清理；
  - **数据库备份成功不等于文件备份成功**：恢复演练必须数据库 + 文件同时恢复，并抽检「任务 → 附件 → 哈希」链路。

## 备选与不采用原因

- 云对象存储（OSS / COS / OBS）：运维最省，但图纸可能不允许出内网（合规待公司云策略），作为后续替换项。
- NAS / 本地盘：不作为主存储，仅作异地副本目标。

## 影响与后果

- MinIO 社区版近年向企业版倾斜（控制台能力收缩、AGPLv3），阶段 0 必须核实许可与版本并锁定；不可用时的替代是 SeaweedFS 等 S3 兼容实现——因只依赖协议，替换成本可控。
- 文件生命周期与版本语义成为产品行为的一部分（临时清理、定档不可变）。

## 切换触发条件

MinIO 许可或功能不满足，或公司云策略变化（评估 SeaweedFS / 云 OSS，接口层不变）。
