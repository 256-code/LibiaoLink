## 覆盖口径

- **读**：右侧模板面板 = `GET /api/v1/task-templates?stage=`（面板数 = `total`、名字与节点顺序 / 节点数都与接口一致；节点标题由读面 join 节点库实时取，不是快照）。
- **新建**：板块标签栏右侧「＋ 新建模板」→ `POST /api/v1/task-templates`（默认名「未命名模板」、空节点）→ 新面板插到最左并把焦点 / 全选落到名字输入框（`version` 0）。
- **保存**：改名 + 拖入节点（左列→面板，指针拖拽）后点「保存」→ `PATCH /api/v1/task-templates/{id}`（`nodeIds` **全量替换** + `version` 乐观锁）→ 回包把面板刷成「已保存」（`version` 0→1、`seq` 10）。
- **刷新后仍在（本刀核心验收点）**：先留一处**不保存**的本地改名 → `Page.reload`（硬刷新）→ 未保存的改动消失、库里那份名字 / 节点 / 已保存态都还在，且面板顺序 = 接口下发顺序（页面不再有任何内存草稿）。
- **乐观锁**：拿旧 `version` 再 `PATCH` / `DELETE` → 409 `VERSION_CONFLICT`（模板不受影响）。
- **删除**：面板红胶囊 → 底部确认条（「模板库里的这一份会被删掉，已经按它生成的项目任务不受影响」）→ `DELETE /api/v1/task-templates/{id}`（带 `version`）= 软删（`deleted_at` / `deleted_by` 置位、`version` 前进到 2）、读面 `total` 回基线、详情 404；**引用行保留**（软删只打标、不连带清子表 —— 照 0009 / 0022 口径，靠 `deleted_at` 过滤），审计 `action=delete` 快照含节点名。
- **同源**：项目总览「添加任务」卡片的模板标签 = 同一份模板接口（计数行「节点 N 个 · 模板 M 块」、标签里的节点与接口一致），点「＋ 添加」照旧走 `POST /api/v1/projects/{id}/tasks` 落库。
- **顺序口径（本刀修订）**：列表 = 九阶段顺序 → `created_at` **倒序** → id —— 「最新在最左」：新建的模板落库后刷新仍在最左（与「＋ 新建模板」插到最左一致）；种子 #9 按清单顺序倒排 `created_at`，所以业务清单第一套（「硬件实施模板一」18 条）仍在「模板二」左侧。
- **零残留**：跑完临时模板软删、临时节点物理删、临时任务逐条软删 + 临时项目软删（`tasks.deleted_at` / `projects.deleted_at` 都核对过）、临时会话撤销；库内活模板 = 种子 #9 的 10 套，无「回放模板-*」/「未命名模板」/「回放节点·模板-*」残留。

## 本轮修掉的问题（回放过程中发现的真问题）

- **新建模板后焦点会丢**：原实现是 `setTimeout(…, 0)` 里 `getElementById` 聚焦，抢在渲染提交前就找不到输入框（回放实测 `document.activeElement` 不是名字输入框）→ 改成 `focusTemplateId` 状态 + `useEffect` 提交后再聚焦 / 全选；回放断言同时校验 `activeElement` 的 `aria-label` 与全选区间（`sel 0 / end 5`）。
- **「刷新后保留」原本验的是假的**：脚本原先用 `Page.navigate` 到同一个带 hash 的地址，那是**同文档跳转、页面根本没重载** —— 面板顺序仍是内存里的顺序。改成 `Page.reload`（真重载）+ 先留一处未保存的本地改名（刷新后必须消失）+ 面板顺序必须等于接口顺序，三条一起才验得住落库。
- **面板顺序会随机**：种子 10 套用同一个 `now()`（事务时间）落 `created_at`，同阶段内只能按随机 uuid 排 —— 硬件实施会变成「模板二」在「模板一」左侧（业务清单反了）。改成：列表按 `created_at` 倒序读 + 种子按清单顺序倒排时间戳（沙箱已重灌种子复核：`硬件实施模板一` 在最左）。
- **拖拽落点会掉到屏幕外**（脚本侧）：同一行等高 —— 空模板面板会被同行的 18 条面板撑高，「拖到这里」的中心点跑到视口外（实测 y=1056 > 1000），真鼠标事件落空。脚本改为一个 evaluate 里先滚目标面板居中再量两支坐标，并用 `elementFromPoint` 自检「卡片能抓、落点在同一块面板内」才拖。
