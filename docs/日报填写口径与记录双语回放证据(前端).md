## 决策记录（过程口径，含两次撤回）

- **分点占位提示先落后撤**：三行分点提示（`1:` / `2:` / `3:`）先按图落地，业务看后撤回（「算了 不要提示文字了」）—— 最终三个多行框无任何占位提示文字，断言按最终态核（`placeholder` 属性全 null）。
- **暂存草稿去掉「左侧卡片」方案**：先按「暂存在日报填写页面吧…左侧还有很多空余空间 暂存为卡片形式」落了左侧卡片，业务随后简化为「暂存就保留表单里面填的内容皆可」—— 落地 = 保留表单 + 顶部提示（不写「日报记录」、不切子视图、不清表单）。
- **附图粘贴优先「真剪贴板 + 真 Ctrl+V」**：回放先 `Browser.grantPermissions(clipboardReadWrite)` + `navigator.clipboard.write` 写真图，再用 `Input.dispatchKeyEvent`（`commands: ["paste"]`）走**浏览器粘贴命令**；只在剪贴板不可用时才回落合成 `ClipboardEvent`（两条路都打在真实 document 监听上）。过程中探到的两个浏览器事实都写进了实现：
  1. 无头页默认**不聚焦** —— 需 `Emulation.setFocusEmulationEnabled`，浏览器粘贴命令才会执行；
  2. Blink 只对**有可编辑焦点**的元素执行粘贴命令 —— 虚线卡自己聚焦不触发 `paste`，故左半内放一个不可见输入框当「粘贴落点」（粘贴一律 `preventDefault`，不落文字）。
- **浏览器把剪贴板位图命名为 `image.png`**：`image.png` 这类通用名与空名一并归入「无名」，按序命名「剪贴板图片-N.png」（避免多张胶囊同名）；有真实原名的（复制文件）保留原名。
- **一次粘贴进两份的坑**：落点输入框的 `onPaste` 与 document 级兜底监听会同时收到同一次事件 —— 去掉落点上的处理器，统一由 document 监听收口（按「最近点过的贴图区」路由）。
- **附图区左右分半 = 业务给样、两半无说明文字**：键帽风（渐变底 + 三层内阴影 + `uppercase` 粗体）+ 右半文件 / 云图标，只有无障碍名（「复制粘贴（点一下再按 Ctrl+V 粘图）」/「点击选择文件（可多选）」）—— 业务口径「都有svg了 还要文字干什么」。
- **图片预览与缩略图共用同一 blob 地址**：「图片要可以预览」—— 缩略图与预览层不为同一张图重复建 URL；预览层铺满视口（`fixed inset-0 z-50` + 半透明底 + 底部文件名），Esc / 点任意处关（与站内浮层同一套关闭口径）。
- **改名只改主名、后缀系统保留**：「自定义把图片png格式删了怎么办」—— 编辑态按**最后一个点**拆「主名 + 后缀」（无后缀 / 点在首尾则整体当主名）；输入框只装主名、后缀以灰字**原位保留**；回车 / 失焦提交拼回、Esc 取消、空名 / 未改不写回。
