# ADR-022 项目更新时间语义：人来动、视图可见的变更才触发 updated_at

- 状态：草案（Proposed）｜评审：lan、px｜随 PR 合并 main 后转「已采纳（Accepted）」
- 日期：2026-09-20｜决策人：wmj（技术负责人）
- 依据：技术设计v0.3-实施与验收.md §7#4、§3.3（M2-04 关键设计）；技术设计v0.2-架构与数据模型.md §2.3、§11.2；系统功能书.md A1-12 / A1-18

## 背景

首页列表默认按「最近活动」排序（A9：缺省 updatedAt:desc），时间区间筛选一期映射 updated_at（A1）。若触发事件集不明确，「谁动了什么才算项目活动」就不可复现：文件上传、日报、系统调度都可能让项目时间漂移，列表次序抖动、筛选取值不可解释。本 ADR 冻结事件集。

## 决策

- **updated_at 语义 = 人参与的、对项目视图可见的业务变更时间**。
- **触发**：① 项目主数据字段变更（code / name / customer / region / project_type / manager_id / description / status 等）；② 项目成员与角色变更；③ 阶段推进与回退（ADR-023）；④ 任务变更（创建 / 编辑 / 状态 / 进度 / 完成 / 软删）——任务属于项目聚合视图，任务活动视为项目活动。
- **不触发**：文件上传 / 定档 / 变更流程（文件与变更各有自身时间字段）、日报与问题、干系人台账、评论、下载与预览、以及系统调度动作（每日「进行中」置位 ADR-025、提醒发送）。
- **实现**：服务层在业务事务内显式 touch（update projects set updated_at = now()）；**不用数据库触发器**（隐式、难测、易漏审计上下文）；由统一工具（ProjectToucher，仓储层单点）保证不漏不重。
- **合并与降噪**：单事务内多次 touch 合并为一次；批量任务操作按受影响项目去重后逐项目一次；调度类写入不 touch。
- **与契约一致**：filter[timeFrom] / filter[timeTo] 按 Asia/Shanghai 日界截断（ADR-028）后映射 updated_at；排序白名单 updatedAt / createdAt / seqNo，缺省 updatedAt:desc（A1 / A9 已入契约）。
- **审计独立**：字段级变更历史（C7-02）与 updated_at 相互独立，前者留全量、后者只做时间戳。

## 备选与不采用原因

- 数据库触发器：隐式链路、测试与排障困难，且无法携带 actor 审计上下文，不采用。
- 仅主数据触发：任务活动不进「最近活动」，首页排序失真，不采用。
- 全事件触发（含文件 / 日报 / 系统动作）：噪音大、次序抖动，夜间调度会全库跳动，不采用。

## 影响与后果

- 列表排序与时间筛选从此可复现；需要专门用例：任务完成 → 项目时间前移；上传文件 / 生成日报 → 不前移；调度置位 → 不前移。
- 触点是单行 UPDATE，1 万行压测下成本可控；批量路径需去重避免 N 次重复 touch。
- 与 M2-04 出口标准（URL 参数直传后端、facets 与列表一致）配套验收。

## 切换触发条件

业务要求「按任务最近活动」等独立维度排序时，新增列（如 task_activity_at）而不是改变 updated_at 语义；若引入项目级聚合缓存，则重新评估触点的位置与批次。
