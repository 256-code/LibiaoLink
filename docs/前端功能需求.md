# LibiaoLink 前端功能需求（后端开发参考）

> 面向后端 / 接口开发同学。现状：前端原型已完成两级页面 ——「项目空间」卡片列表与「项目详情」项目总览任务表（分支 `px`，commit `ef4d3f6`，Push 6）。业务数据均为浏览器内存示例，认证走公司统一登录（Casdoor，标准 OIDC）。本文档描述**已实现的页面与功能**及**所需后端接口**，用于后端开发与联调对接。
>
> **维护约定：前端每次改动（页面 / 交互 / 数据模型 / 接口需求）必须同步更新本文档，并与改动同一次推送提交（见仓库根 `AGENTS.md`）。**

## 一、页面与交互（前端已实现）

### 1. 登录与会话

- 前端不承接登录表单：未认证自动跳转公司统一登录（Casdoor，标准 OIDC，PKCE + state）。
- 登录回跳后通过 `/auth/me` 获取用户；认证中转场为无框 8 圆点加载动画，失败展示「加载失败 + 重试」。
- 账号口径遵循公司接入标准：`Name = 工号`（如 `zhangsan`）、`DisplayName = 张三`、`Email = zhangsan@libiaorobot.com`。

### 2. 全局顶栏

- 左侧：LibiaoLink Logo 与副标「立镖全链路信息平台」，点击返回「项目空间」。
- 进入项目详情后，Logo 右侧显示面包屑：`项目空间 / 项目编号`，副行「项目描述 · 更新于 时间」（视口较窄时隐藏）。
- 右侧账号区：圆形头像（取 DisplayName 首字符，浅灰底），悬停提示「姓名 · 邮箱」；点击展开菜单，当前仅「退出登录」一项；点击外部或 Esc 关闭。

### 3. 首页「项目空间」

- 项目卡片网格：每行 4 列，随屏幕宽度自适应降列（1 / 2 / 3 / 4 列），页面为全宽布局。
- 卡片内容（自上而下）：右上角浅灰序号徽标（两位）、小车图标（彩色，卡片内唯一高饱和元素）+「项目经理：xxx」、项目编号（等宽字体，如 `CNBJ-20260708-0001`）、项目描述、右下角更新时间（`YYYY-MM-DD HH:mm`）。
- 悬停：卡片轻微放大 + 主题色光晕。
- 标题区：`项目空间` + 项目计数（搜索时切换为「找到 N 个项目」）。

### 4. 搜索

- 输入即过滤（实时），匹配范围：项目编号 / 描述 / id / 更新时间 / 项目经理（不区分大小写）。
- 一键清空；无结果时显示空态与「清空搜索」按钮。

### 5. 新建项目

- 点标题区「新建项目」按钮打开居中弹窗。
- 表单三项：项目编号、项目描述、项目经理；三项均必填（全部填写后「创建项目」才可点击）。
- 关闭方式：取消按钮 / Esc / 点击遮罩。
- 创建成功后：新项目追加到列表末尾；序号、时间（当前时刻）、主题色由前端自动分配。
### 6. 项目详情页「项目总览」

进入方式：首页点击项目卡片，路由切到 `#/project/{项目id}`；可直接输入 URL 直达，项目不存在时显示「未找到该项目」。

**6.1 阶段标签导航**

- 10 个标签：项目总览 + 9 个施工阶段（售前规划 / 设计开发 / 加工采购 / 组装发货 / 硬件实施 / 软件部署 / 试运行 / 生产阶段 / 验收）。
- 默认选中「项目总览」；点击其它阶段，表格过滤为该阶段任务；标签栏可横向滚动。

**6.2 项目总览汇总卡**

- 当前阶段：按阶段顺序找到第一个「存在未完成任务」的阶段；全部完成时显示「全部完成」。
- 逾期 N 条：未完成且预计完成日期早于今天的任务数（红色，0 条时为正常色）。
- 整体进度：进度条 + 百分比 + 「N/M 完成」（完成数 / 总任务数）。

**6.3 阶段分组任务表**

- 按 9 个阶段分组，仅渲染有任务的阶段；组头可点击折叠 / 展开（默认展开）。
- 组头：折叠箭头 + 胶囊；胶囊内嵌淡绿色「液体」背景，液面高度 = 该阶段完成率（完成数 / 该阶段任务数）；右侧「N/M 完成」。
- 表头 15 列（按显示顺序）：任务描述（常显锁定）、项目经理、任务负责人、任务状态、紧急重要度、是否按时交付、输出成果文件、文件、项目进展描述、开始日期、预计所需天数、预计完成日期、预计所需施工人数、实际完成日期、变更关联。
- 列宽策略：任务描述列固定 340px；其余列按「最小宽度」配比弹性伸缩；表格总宽 = 各显示列最小宽之和，视口不够时出现横向滚动（任务描述列不被挤压）。
- 行内元素：
  - 任务描述：中文标题 + 英文标题（灰色小字，截断悬浮看全）；行内右侧固定 4 格进度条（位置不随列筛选移动）。
  - 任务状态：圆点 + 文案（已完成 = 绿、进行中 = 蓝、待开始 = 灰）。
  - 紧急重要度：徽标（高 = 红、中 = 琥珀、低 = 灰）。
  - 是否按时交付 / 输出成果文件：浅色徽标；空值显示「—」。
  - 文件：文件名截 4 字 + `+N`，悬浮显示全部文件名。
  - 预计所需天数：渲染为开始日期与预计完成日期之间的短横线，横线上方仅显示数字。
  - 实际完成日期：已完成显示日期；未完成且逾期显示红色「逾期」；否则「—」。
  - 变更关联：有变更日期时显示琥珀色「变更」徽标，悬浮显示日期。
- 行交互：整行可点击（键盘 Enter / 空格同效），点击打开任务详情抽屉；选中行显示琥珀色左侧条与浅底。

**6.4 行内四格进度条（Tracker）**

- 4 格状态：全灰 = 未开始；1 格绿 = 刚开工；2 格 = 完成一半；3 格 = 快完成了；4 格 = 完成了。
- 悬停：进度条左侧浮现文字状态并高亮到悬停格；悬浮提示「项目进度：X」。
- 点击第 N 格：进度设为 N/4（前 N 格点亮）；点击当前已点亮的最后一格回退一格（误点修正）。
- 进度条固定在任务描述列内，不随列筛选 / 滚动移动。

**6.5 任务详情抽屉**

- 触发：点击任务行；从右侧滑入（宽 460px，小屏 94vw）；点遮罩或 Esc 关闭。
- 头部：阶段胶囊、状态胶囊、（逾期时）红色「已逾期」胶囊、关闭按钮；中文标题 + 英文标题。
- 进度区：「项目进度」+ 文字状态 + 进度条；（逾期时）红色提示「已超过预计完成日期（M月D日），当前仍未完成」。
- 字段区（14 项全部展示，不受表格列筛选影响）：项目经理、任务负责人、任务状态、紧急重要度、是否按时交付、输出成果文件、文件（全部文件名）、项目进展描述、开始日期、预计完成日期、预计所需天数、预计所需施工人数、实际完成日期、变更关联。

**6.6 字段筛选（列显隐）**

- 表格右上「筛选」按钮，下拉面板列出全部 15 列，可勾选显示 / 隐藏。
- 常显列（任务描述）锁定不可取消，标注「常显」；面板内提供「重置」恢复默认列。
- 默认隐藏：文件、项目进展描述、预计所需施工人数；其余默认显示。
- 「预计所需天数」依赖开始日期与预计完成日期两列，二者任一隐藏时该列自动隐藏。

**6.7 底部横向滑块**

- 表格横向溢出时，页面底部（sticky）出现自定义滑块条；不溢出时自动隐藏。
- 支持拖动滑块、点击轨道跳转、键盘左右键（步进 160px）。
- 表格自身原生横向滚动条隐藏，避免与滑块重复。

### 2. 任务 ProjectTask（本次新增）

| 字段 | 类型 | 说明 | 示例 |
|---|---|---|---|
| id | string | 任务唯一标识 | t01 |

| progress | number | 进度：0 / 0.25 / 0.5 / 0.75 / 1 | 1 |
| startDate | string | 开始日期（原型为中文短日期） | 5月15日 |
| dueDate | string | 预计完成日期 | 5月20日 |
| doneDate | string | 实际完成日期（空 = 未完成） | 5月20日 |
| days | number | 预计所需天数 | 6 |
| deliverable | string | 输出成果文件（可空） | 验收单 |
| change | string | 变更关联日期（可空） | 2026/8/11 |
| onTime | string | 是否按时交付（可空） | 按时交付 |
| note | string | 项目进展描述（可空） | 物料清单 |
| headcount | number | 预计所需施工人数 | 10 |
| priority | 枚举 | 紧急重要度：高 / 中 / 低 | 高 |

- 项目经理在原型中为项目级常量（`PROJECT_MANAGER`），任务行与抽屉统一展示。
- 完成判定：`doneDate` 非空或 `progress >= 1`；逾期判定：未完成且 `dueDate` 早于今天（按 月 / 日 比较）。
- 演示数据 44 条任务；施工人数 / 紧急重要度 / 文件为原型派生演示值（源表对应列为空，待后端定来源）。

## 三、后端接口需求（建议契约）

统一前缀建议 `/api/v1`，JSON；认证复用现有 OIDC 会话（HttpOnly Cookie 或 Bearer 均可，前端当前用 Cookie）。

### 1. 项目列表 `GET /api/v1/projects`（前端已用）

- query：`keyword`（可选，服务端过滤，语义同前端）、`page`、`pageSize`（建议默认 20）
- resp：`{ "items": Project[], "total": number }`

### 2. 新建项目 `POST /api/v1/projects`（前端已用）

- req：`{ "title": …, "description": …, "manager": … }`
- 建议服务端校验 `title` 唯一；`updatedAt` 由服务端生成（ISO 8601 带时区，前端本地化显示）
- resp：201 + 完整 Project 对象

### 3. 任务列表 `GET /api/v1/projects/{id}/tasks`（新增，前端待接入）

- query：`stage`（可选，按阶段过滤）
- resp：`{ "items": ProjectTask[], "total": number }`，每条含全部字段（含 files），供表格与抽屉直接渲染
- 建议随列表一并返回汇总（当前阶段、逾期条数、完成数），或使用第 6 条独立接口

### 4. 任务进度更新 `PATCH /api/v1/projects/{id}/tasks/{taskId}/progress`（新增，前端待接入）

- req：`{ "progress": 0.25 }`（取值 0 / 0.25 / 0.5 / 0.75 / 1）
- 服务端联动：更新 `status`（待开始 / 进行中 / 已完成），完成时回填 `doneDate`，可选更新项目 `updatedAt`
- resp：200 + 最新 ProjectTask（前端以返回值覆盖行内状态）
- 权限与审计：建议校验操作人（项目经理 / 任务负责人 / 管理员），记录操作日志

### 5. 任务详情 `GET /api/v1/projects/{id}/tasks/{taskId}`（可选）

- 抽屉当前复用列表数据；若列表后续不下发全部字段（files / note 等），抽屉打开时按需拉取

### 6. 项目总览汇总 `GET /api/v1/projects/{id}/summary`（可选）

- resp：`{ "currentStage": …, "overdue": 3, "done": 12, "total": 44 }`，用于汇总卡

### 7. 列显隐偏好 `PATCH /api/v1/users/me/preferences`（可选）

- req：`{ "taskTableHiddenColumns": ["files", "note", "headcount"] }`
- 用于跨设备记住用户勾选的表格列（当前为前端内存态，刷新回默认）

### 8. 后续建议（前端尚未实现，接口预留）

- `PATCH /api/v1/projects/{id}`：编辑（描述、项目经理等）
- `DELETE /api/v1/projects/{id}`：删除
- `GET /api/v1/projects/{id}`：项目详情

### 9. 已有接口（前端已接入，无需新增）

- `/auth/login`、`/auth/callback`、`/auth/me`、`/auth/logout`（本地开发为 Vite 中间件，生产环境需按 `frontend/README.md` 迁移到后端实现）
## 四、字段校验与规则

### 1. 项目字段

| 字段 | 必填 | 规则 |
|---|---|---|
| title | 是 | 建议格式：四大写字母-日期-四位序号（如 `CNBJ-20260708-0001`）；建议全局唯一 |
| description | 是 | 中文短语，建议不超过 30 字 |
| manager | 是 | 姓名 |
| updatedAt | 只读 | 服务端生成 |
| accent | 只读 | 服务端下发或前端分配（待确认，见第六节） |

### 2. 任务字段

| 字段 | 必填 | 规则 |
|---|---|---|
| stage | 是 | 必须属于 9 个施工阶段枚举 |
| title | 是 | 中文任务描述 |
| owner | 是 | 姓名 |
| status | 是 | 枚举：已完成 / 进行中 / 待开始，与 progress 联动 |
| progress | 是 | 0 / 0.25 / 0.5 / 0.75 / 1；等于 1 视为完成 |
| startDate / dueDate / doneDate | 否 | 原型为「M月D日」中文短日期；建议后端用 ISO 8601，前端本地化展示 |
| days | 否 | 整数；建议由开始 / 预计完成日期推导，避免与日期矛盾 |
| headcount | 否 | 正整数（人）；源表为空时当前由前端演示值兜底 |
| priority | 否 | 枚举：高 / 中 / 低；源表为空时当前由前端演示值兜底 |
| onTime | 否 | 如「按时交付」；空 = 未交付 |
| files | 否 | 文件名数组；建议限制类型与大小，前端只读展示 |

## 五、非功能需求

- 排序：项目默认按 `updatedAt` 倒序或创建顺序（待确认；原型为创建顺序）；任务按阶段顺序 + 表内原始顺序。
- 分页：项目与任务数量增长后必须分页（原型为全量渲染：项目 20+、单项目任务 44）。
- 搜索：建议服务端过滤（前端当前为本地过滤，仅适用小数据量）。
- 错误处理：接口失败时前端需要提示（原型未实现，接口就绪后补）。
- 时区：统一 Asia/Shanghai；时间字段建议 ISO 8601 带时区，前端本地化展示。
- 权限：新建 / 编辑 / 删除项目、更新任务进度的权限模型待定（建议接入 Casdoor Roles / Permissions）。
- 状态保持：任务进度、列显隐、新建项目在前端原型均为内存态，刷新回默认；接入后端后由服务端持久化。

## 六、待确认问题（需与 SSO 管理员 / 后端对齐）

1. 项目编号由前端输入还是后端生成？唯一性由谁保证？
2. 主题色 `accent` 由服务端下发还是前端分配？
3. 新建 / 删除 / 更新任务进度的权限：按组织、部门还是角色控制？是否需要操作审计？
4. 项目与任务数据是否与 Casdoor 用户体系关联（项目经理、任务负责人是否取自用户表 / 工号）？
5. 项目数量级与分页策略；单项目任务量（原型 44 条）与多项目后的规模。
6. 任务数据来源：是否由源表格（Excel）导入？导入频率与覆盖策略（全量重导 / 增量更新）？
7. 任务进度是否允许回退（当前原型支持回退到点击格）？回退是否需要写回与审计？
8. 源表为空的三列（预计所需施工人数 / 紧急重要度 / 文件）由谁维护、如何取值？
