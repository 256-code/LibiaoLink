## 未覆盖 / 风险登记

- **压测未做**：并发 2~4、200MB 级长跑内存曲线、转换成功率 ≥95%（PoC-1 真实样本集）不在本脚本范围（属 M4-05 压测 / M8 容量验证）；本脚本只证「接线正确 + 通道打通 + 降级可控」。
- **预览产物对象的清理未接**：彻底删除 / 回收站到期目前只清 `projects/` 前缀下的版本对象，`previews/` 前缀的产物对象与 `preview_artifacts` 行（随 files 级联删除）需在 M4-05 收口时按 content_hash 反查引用后清理（迁移 0027 的口径已写明）。
- **dead 重投**：`failed` 是缓存态（管线修复后由 `pipeline_version` 递增失效）；dead 任务由读取侧（PR-11）幂等补投唤醒（`appendOutboxIfAbsent`）。

## 验收对照（PR-10 / M4-05 转换队列切片）

- **定档预生成（P1）** = F2：定档前无任务、定档后 outbox 精确落一条 `preview.job`（去重键 = `preview.job:{contentHash}:{pipelineVersion}:{target}`），投递与业务在同一事务（与 `file.finalized` 同批）。
- **队列消费与产物** = W1 / W2 / W3：worker 领任务 → 读源字节 → 调转换沙箱 → 产物回对象存储 → `preview_artifacts` ready（`object_key` / `generated_at` 成对）；对象键 = 三元组，content-type = `application/pdf`，产物内嵌 Noto CJK（「中文不乱码」的字体层证据），元数据留痕三元组 + 源版本 + 转换模式。
- **三元组幂等（D2-06「同一内容只转一次」）** = Z1：同内容第二个文件定档 → 任务行恒为 1（`appendOutboxIfAbsent` 不覆盖已有进度）、产物行恒为 1 且 `version_id` 仍是首次生成者、`generated_at` 未被重写（无二次转换）。
- **失败降级（D2-05「请下载查看」）** = Z2：101 MB 源文件超上限 → 不调转换器、产物 `failed`（`error` ≤ 500 字、`object_key` 为空）+ outbox `dead`（`attempts=1`，不重试），降级只影响预览。
- **不占配额** = Z3：判不出渲染通道的类型（`.zip`）不投递任务、不留失败行。
- **未在本脚本覆盖**（见上「未覆盖 / 风险登记」）：并发 / 200MB 长跑 / 成功率 ≥95%；预览产物对象清理；转换器镜像分发。

## 真机暴露的缺陷（已随本 PR 修复）

- **outbox 领取 SQL 在真库报 `malformed array literal: "preview.job"`**（单元测试用替身、抓不到）：drizzle 的 `sql` 模板会把 JS 数组**摊平成多个绑定参数**，`topic = any(${topics}::text[])` 实际只收到单个字符串元素 → PG 当作数组字面量解析失败。修复 = 用 `sql.join` 显式拼成 `topic in ($1, $2, …)`（每一项仍是绑定参数，不拼字符串）；修复后同一脚本 11/11 断言通过。**教训**：领取器这类「只有真库能验」的 SQL 必须进真机回放（本脚本可当门禁，退出码 0 = 全过）。
- **回放收尾漏删项目快照**（`project_stages` / `project_nodes` 外键挡住 `projects` 删除 → 回放项目残留）：已在脚本收尾补齐「节点需求 → 节点 → 阶段 → 成员 → 项目」删除顺序，重跑后零残留（本目录第 2 次回放的收尾无 WARN）。
