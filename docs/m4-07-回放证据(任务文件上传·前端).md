## 备注 / 决策记录

- **「同款」怎么验**：①a 不比对写死的颜色值，而是取**同一行**里最近的一个 `[data-inline-cell=editor]`（本轮实测 = 「修改项目经理」单元格）逐项比对 `borderRadius / backgroundColor / borderTopWidth / paddingTop / paddingLeft / fontSize / backdropFilter / boxShadow` —— 全等才算过；Tailwind 4 计算色值落在 `oklab()`，写死 `rgba()` 的断言会假阴性（首轮实测踩过，已改）。
- **「点击后抽屉也出现」的根因与修法**：隐藏 `input` 上的 `.click()` 会打开选择框；对话框关掉后浏览器还会向该 input **补发一次 click** —— 这次 click 从 input 冒泡到行（行点击 = 打开详情抽屉），于是「上传」连带把抽屉打开了。修法 = 隐藏 `input` 加 `onClick` 拦冒泡（`TaskBoard.tsx`）。回归双锁：②e（真实选完文件后抽屉没开）+ ②f（向 input 主动派发冒泡 click，抽屉仍不开）。
- **②f 探针的洁癖**：直接向 `input type=file` 派发 click 会因缺 user activation 让 Chrome 打一条 `File chooser dialog can only be shown with a user activation` 警告 —— 探针临时把 `type` 切成 `text` 再派发（只验冒泡链路），控制台保持 0 条。
- **预览产物 vs 原文件下载（2026-09-30 定案）**：下载走 `GET /files/{id}/versions/{versionId}/download-url` —— 签名 `version.objectKey`（`projects/…/v{n}/{hash}.{ext}` 上传原始对象）+ `attachment` + 原文件名；预览产物在 `previews/{contentHash}/{pipelineVersion}/{target}` 前缀、只用于内联渲染。**浏览器内置查看器工具栏自带的下载拿的是 iframe 里的预览产物**（Office / 文本 → 转换出的 PDF，这就是「下载都是 PDF」的来源）；抽屉每行「下载」与浮层「下载原文件」统一走版本签名 —— 落盘 = 原文件字节 + 原文件名（④p2 / ④p4 字节级比对），每下载一次写一条 `action = download` 审计（④p3）。
- **文件名 / 「+N」口径**：列内 = 第一份文件名（截断 + `title` 全名单）+ 其余「+N」（业务口径「超出长度后面写+1 +2」）；映射按项目一次拉全量（`fetchTaskFileNames`，`limit=200` 分页），取不到 / 老数据退回「N 份」—— 两条路都不出「未定档」签。
- **去定档签口径**：列表与抽屉都不再出现「未定档 / 已定档」（业务口径「定档是整个项目的定档安排 不是文件来区分的」）；抽屉状态签只留 已变更 / 已归档 / 回收站；定档交互留待定档那一刀。
- **图片预览口径**：与日报 / 问题附图同款 —— 行内 40×40 缩略图（`usePhotoUrl` 懒取签名）+ 点开大图浮层；Esc 先关浮层（capture 拦 keydown），不连带关抽屉；预览签名轮询预算 20s（worker outbox 领取间隔 5s）。
- **PDF / Office / 文本预览口径**（业务口径「这个pdf我也打不开啊」）：`previewKindOf` 与 `server/src/modules/file/preview.targets.ts` 同一分类 —— 图片走 `image` 通道（缩略图 / img），PDF / Office / 文本走 `pdf` 通道（PDF 源直通、Office / 文本经 soffice 出 PDF）；抽屉里给「预览」按钮、浮层用**浏览器内置查看器**（iframe + 短时签名 URL）；Esc / 点浮层关闭，均不连带关抽屉；首次预览需等转换（轮询 20s 内出，失败仍降级提示）。
- **改名口径**：只改主名、后缀原位保留（同日报附图「自定义把图片 png 格式删了怎么办」口径）；空名 / 没改不写回；Enter / 失焦提交、Esc 取消。
- **删除口径**：回收站（M4-02，30 天可恢复），第一下出确认条、第二下才落库；recycled 不进详情清单、不进列计数与文件名映射（列表接口默认排除）。
- **服务端配套一（代扩，请 wmj / lan 复核）**：`FileRenameBodySchema` + `PATCH /api/v1/files/{id}` —— 乐观锁 409 / 回收站 409 / 同名幂等不升 version / 审计；`generate` / `check` 零漂移（86 paths / 232 schemas）。
- **服务端配套二（预览投递修复）**：同内容重传时 `preview.job` 去重键撞历史 `done` 行、产物行被清后永远 `not_ready` —— `appendOutboxIfAbsent(..., { reviveDone })` 唤醒时**连 payload 一起刷新**（旧载荷指向已删 fileId，worker 会跳过），`preview-read.service.ts` 补投一律带 `reviveDone: true`。
- **权限**：入口暂未按 `file.upload` / `file.delete` 权限键收敛（沙箱 `PERMISSION_ENFORCED=false` 下测不出差异）—— 收敛需把权限画像透传到 `ProjectDetail`，留作后续；下载按契约已判 `file.download`（缺权限 403 → 行内提示服务端文案）。
- **零残留口径**：四份回放文件回收 → purge（对象真删 + 元数据删 + 留痕）；临时项目物理删 —— **先 purge 文件再删项目**（绕行 `ProjectRepository.hardDeleteWithVersion` 先删 `file_versions` 撞 `fk_files_current_version` 的已知问题，挂 wmj 线）；会话撤销；`audit_logs` 只读不动。
- 页面控制台 / 异常：0 条。

## Push 249 增量（任务定档确认 · 定档后任务不支持任何修改 · 「文件」列改别的字段消失的修正）

> 业务口径（2026-10-08）：①「添加和替换文件要提示是否为定档文件，若是则上传文件后该任务定档不支持任何修改」；②「当我修改别的信息 文件一栏的内容就消失了 要刷新才能回来」。

- **定档确认**（`TaskFilesPopover.tsx`）：点「＋ 添加文件」/ 未定档（draft）行的「替换」先出行内一问（`data-task-files-finalize-prompt`）「是否为定档文件？」——「是，定档」（`data-task-files-finalize-yes`）= 传 / 换完成后对该文件定档（`fileApi.finalizeFile` → `POST /files/{id}/finalize`）；「否，仅上传」（`-no`）= 普通 draft；已定档 / 已变更行的「替换」不弹此问（照旧先填「变更原因」）。
- **任务随定档锁定**（服务端同事务）：文件 final 的同时置位 `tasks.finalized_at / finalized_by`（幂等）+ 写一条 `object_type=task` 审计；此后任务写口全 409 `TASK_FINALIZED`（任务侧编辑 / 批量 / 进度 / 完成 / 删除 / 锁定字段例外调整 + 文件侧新增上传 / 直替 / 改名 / 普通回溯），唯一保留通道 = 已定档文件的变更（A4-13）。
- **已定档界面**：下拉顶常驻提示（`data-task-files-note-finalized`「任务已定档：不支持新增 / 改名 / 草稿替换；文件修改走「替换」变更」）；点「＋ 添加文件」/ 草稿行「替换」不再开选文件框，改出提示行（`data-task-files-note-finalize`）。
