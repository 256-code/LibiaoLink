# ADR-014 测试与 CI：轻量分级（L1 / L2 / L3）+ 三条红线

- 状态：草案（Proposed）｜评审：lan、px｜随 PR 合并 main 后转「已采纳（Accepted）」
- 日期：2026-09-18｜决策人：wmj（技术负责人）
- 依据：技术设计v0.1-选型分析.md §4.19、§7.5.2、§5（#15）；CONTRIBUTING.md §17

## 背景

3 人团队 + AI 代理高产出的工作方式：CI 必须存在，但不能拖慢迭代。仓库现状已有 GitHub Actions 对 frontend 做 typecheck + build（L2 雏形）。

## 决策

**保留 CI，做小做快，分三级**：

| 层级 | 时机 | 内容 | 时间预算 |
|---|---|---|---|
| L1 本地钩子 | 每次提交（pre-push） | 格式化、lint、typecheck、受影响范围单测 | 30 秒 ~ 2 分钟 |
| L2 合并前 | PR / 合并窗口 | 完整单测 + 从零数据库迁移 + 集成测试（约束 / 并发 / 文件管道冒烟） | 5 ~ 15 分钟 |
| L3 夜间 | 定期，不阻塞开发 | E2E 关键路径、权限矩阵、依赖漏洞扫描、恢复演练（每月） | 夜间执行 |

**三条不可省的红线**：

1. 空库迁移能跑通（生产救火能力，每次合并前验证）；
2. 类型与测试基线（回归由机器拦截，而不是上线后由用户发现）；
3. 镜像可重复构建（测试通过的版本 = 部署的版本）。

提速手段：只跑受影响范围（workspace 过滤）、依赖与构建缓存、测试分片并行；E2E 只保留冒烟在 L2、全量放 L3；可用自托管 runner 或定时脚本替代云 CI（效果等价、成本更低）。

## 备选与不采用原因

取消 CI / 纯本地脚本：3 人团队下机器守门比人可靠；最低限度也必须做到「合并前在干净环境跑通迁移 + 集成测试并留痕」——这是不可再退的底线。

## 影响与后果

- server / database / shared 落地后按 L1~L3 扩展 CI（阶段 5 · CI 扩展，由 px 执行，wmj 提供门禁需求）。
- 权限矩阵不变量（ADR-011）与规则金标回放（自动化规则 PoC）纳入 L2 / L3。
- 未执行或失败的检查必须明确报告（CONTRIBUTING §17）。

## 切换触发条件

团队扩大或发布频率提升，评估更强门禁（自托管 runner / 更完整的流水线）。
