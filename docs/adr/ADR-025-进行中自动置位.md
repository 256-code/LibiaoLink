# ADR-025 「进行中」自动置位：每日 00:05 批量置位 + task_events 记来源 system

- 状态：草案（Proposed）｜评审：lan、px｜随 PR 合并 main 后转「已采纳（Accepted）」
- 日期：2026-09-20｜决策人：wmj（技术负责人）
- 依据：技术设计v0.3-实施与验收.md §7#7、§3.4（M3-02）；技术设计v0.2-架构与数据模型.md §2.4 / §6.2；系统功能书.md A1-06 / A1-10 / 2.9

## 背景

任务基础态是 pending / active / done 三值，展示五态由日期派生；「进行中」既可由人工写入（A12 · Push 70），也需要系统在计划开始日后自动置位，否则任务会长期停在「待开始」而无法沉淀真实状态与事件流。自动置位还必须避免与人工写入、规则提醒、项目时间语义互相污染。

## 决策

- **调度置位**：每日 00:05（Asia/Shanghai，ADR-028）扫描 status = pending 且 planned_start 不晚于今天的任务，置为 active；写 task_events，来源标注 system（actor = system）。
- **进度不变量同步**：置位同时应用 A12 的联动不变量——active 的任务进度至少 1 格（0 → 0.25），保证「1 格＝刚开工」的展示口径一致；其余档位不动。
- **不触发项目时间**：置位属系统动作，不写 projects.updated_at（ADR-022），避免夜间全库项目时间跳动。
- **不触发提醒**：置位本身不发送消息；R03 / R04 / R05 等按各自窗口独立判定（ADR-009 / M5）。
- **幂等**：以「作业标识 + 日期」为 dedupe_key（幂等表口径），重跑 / 补跑不重复写事件、不重复置位。
- **不覆盖人工状态**：只做 pending → active；已被人工置为 active / done 或已软删的任务跳过；人工把任务改回 pending 且计划开始日已过时，次日调度会再次置位（可接受，事件流可查）。
- **缺计划开始日不置位**：无 planned_start 的任务不自动开工，保持人工掌控。

## 备选与不采用原因

- 读时派生（不落库）：无法留痕、无法触发事件与统计（A1-10 要求留痕），不采用。
- 实时 / 每小时置位：噪音高、无业务意义，不采用。
- 不自动置位（全靠人工）：状态与事件流长期失真，不采用。

## 影响与后果

- 调度框架复用 ADR-005 的 jobs + advisory lock 单例；ClockService 注入（禁止取系统时间），便于金标回放与补跑。
- 用例：计划日开始 → 次日置位（含进度 0 → 0.25）；未到日期 → 不置位；无日期 / 已完成 → 跳过；重跑幂等；项目 updated_at 不变。
- 与 A12 人工写入共享同一条状态写入服务，避免两套联动逻辑。

## 切换触发条件

若业务要求「开工需人工确认」或需要按项目配置置位时刻，改为按项目策略表驱动；若任务量导致 00:05 窗口过长，改为按索引分批 + 断点续跑。
