# ADR-019 蓝图组织：按项目类型各一份蓝图 + 默认模板兜底（版本化）

- 状态：草案（Proposed）｜评审：lan、px｜随 PR 合并 main 后转「已采纳（Accepted）」
- 日期：2026-09-20｜决策人：wmj（技术负责人）
- 依据：技术设计v0.3-实施与验收.md §7#1、§3.3（M2-02）；技术设计v0.2-架构与数据模型.md §3.1 / §3.4 / §3.5；系统功能书.md A1-12 / A1-16 / C9-06 / C9-07

## 背景

不同项目类型的交付流程不同（节点集合、必交成果物不同），业务在建任务时明确要求「按所属项目类型的流程节点模板生成任务清单」（A1-16 / C9-06）。v0.2 §3.1 与 ADR-015 原定「蓝图全局唯一」，无法承载类型差异；同时建项目按蓝图导入生成快照、节点 key 稳定、门禁按 node_requirements 判定这些既有不变量必须保持。

## 决策

- **蓝图按项目类型组织**：蓝图带 project_type 维度，每个项目类型可各维护一份蓝图；另设一份**默认模板**（project_type 为 default 的特殊行）作为兜底。
- **默认模板 + 类型覆盖 = 编辑期约定，不是运行时继承**：类型蓝图是「在默认模板基础上编辑出来的完整独立 JSON」，发布时就是完整快照；导入时优先取该类型的已发布蓝图，缺失时回落默认模板。不引入运行时继承 / diff 合并，避免半继承带来的校验与门禁歧义。
- **版本化语义不变**：每个蓝图（含默认模板）各自独立递增 blueprintVersion；发布产生新版本；已生成项目为导入快照，不受后续蓝图变更影响（source_blueprint_version 记录到具体蓝图的具体版本）。
- **契约增 projectType**：BlueprintSchema 增可选 projectType 字段；BlueprintView 标明所属 type 与「是否默认模板」；契约切片登记到 M0-02（随 M2 落地，不改变现有路径）。
- **校验规则不变**：schemaVersion / 阶段与节点 key 唯一 / seq 递增 / docType 存在于成果文件字典 / 全量 issues 一次性返回（v0.2 §3.4）。
- **维护权限**：蓝图（模板）的保存 / 发布 / 导入仅管理员（与 ADR-020 一致）。

## 备选与不采用原因

- 全局单一蓝图：无法承载类型差异，A1-16 的「按类型生成」落不了地，不采用。
- 运行时继承（类型蓝图 = 默认模板 + 差异补丁）：合并语义复杂，校验 / 门禁结果依赖两层求值，排障成本高，不采用。
- 每个项目自定义蓝图：与「模板受控 + 项目内只做增删留痕」的产品口径冲突，不采用。

## 影响与后果

- 新增表：blueprints（project_type 维度，含默认行）、blueprint_versions（按蓝图独立版本序列、保存完整 JSON 与校验结果）；v0.2 §3.1 的「全局唯一」表述由本 ADR 修订。
- 取蓝图逻辑收敛到单点（BlueprintService.currentByProjectType(type)）；建项目事务按项目类型取版本并在 node_key 唯一约束下幂等生成（v0.2 §3.5 流程不变）。
- 运维动作标准化：新增项目类型 = 复制默认模板 → 编辑 → 发布，无需改代码、无需迁移。
- 高风险评审范围（契约 + 迁移 + 架构），合入 main 前需非作者评审（CONTRIBUTING §15）。

## 切换触发条件

项目类型数量或蓝图差异维度膨胀到难以按类型维护（如出现类型 × 地区 × 客户的组合差异），或业务要求蓝图变量化 / 继承时，重新评估蓝图继承机制或模板 DSL。
