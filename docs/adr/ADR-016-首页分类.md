# ADR-016 首页分类：项目主数据扩展 + 侧边栏多维筛选（不建独立报表门户）

- 状态：草案（Proposed）｜评审：lan、px｜随 PR 合并 main 后转「已采纳（Accepted）」
- 日期：2026-09-18｜决策人：wmj（技术负责人）
- 依据：技术设计v0.1-选型分析.md §4.21 相关口径、§5（#17）；技术设计v0.2-架构与数据模型.md §8.2；Q26 / Q28

## 背景

业务要求首页可按「地区、项目类型、负责人」等维度分类查看项目；「地区」口径 = **项目落地地区**（已确认）。300 人规模不需要独立的数据门户。

## 决策

- 项目主数据扩展分类字段（地区 / 项目类型等，取值随 C9 字典固化）。
- 首页侧边栏多维筛选 + 计数（facets）：后端提供 facets 接口，计数与列表**同口径**（同一过滤条件）；筛选态写入 URL query（可分享 / 收藏）。
- 实现要点：filter[...] 查询参数口径与索引（如 ix_projects_facets、ix_projects_stage）按技术设计v0.2 §8.2；地区字典含「未分类」的维护归属待确认。
- 不建独立报表门户 / 统计站点；统计与下钻走 dashboard 接口。

## 备选与不采用原因

独立统计门户：重复建设，且权限出口不一致的风险高（统计口径必须与列表一致）。

## 影响与后果

- 分类字段的字典维护（谁维护地区字典、历史项目补录规则）属业务待确认项（Q28）。
- facets 接口与列表接口必须共享同一过滤构造，避免「计数与结果对不上」类缺陷。

## 切换触发条件

分类维度超过 5 个，或业务要求自定义维度时，评估可配置筛选框架。

## 待复核差异

- 2026-09-18（Push 33）：本 ADR 背景中的「负责人」按业务口径更正为「项目经理」。项目级唯一责任人为「项目经理」（`projects.manager_id`，必填；首页筛选参数 `filter[managerId]`，多值逗号分隔），任务级责任人为「任务负责人」（`tasks.owner_id`）；不存在「项目总负责人 / 项目负责人」。本 ADR 的决策方向（自建分类 + 侧边栏多维筛选、facets 同口径、筛选态入 URL）不变，术语已同步回写技术设计v0.2 §8.1 / §8.2 与系统功能书 A1-18。
