# Push 186 回放证据（前端：抽屉滚动锁补偿 —— 开关抽屉整张表不再抖动）

> 业务口径：px 报「展开抽屉后 再关闭 整个表格会抖动」—— 本刀修掉。
> 根因：抽屉打开时把 `overflow: hidden` 写进 body → 纵向滚动条消失 → 视口瞬间宽出一个滚动条宽（Windows 经典滚动条实测 **15px**）
> → 任务表列宽按比例分配（弹性网格），整张表被横向撑开 15px；关抽屉再缩回来 —— 一开一关就是「抖两下」。
> 修法：锁滚动**之前**先量出滚动条实测宽度，再补一份等宽 `padding-right`（新增 `frontend/src/scrollLock.ts`；`TaskDrawer` 的锁滚动 effect 改调它）。

## 汇总

- **22 / 22 项全过**（脚本自清理：任务软删 → 项目软删 → 节点物理删 → 临时会话撤销，库内零残留）。
- 关键口径：① **滚动锁本身没丢** —— 打开时 `body.overflow = hidden`（用户滚动仍被拦住），只是**同时**补了等宽内边距；
  ② **表格逐像素不动** —— 表格宽 / 左边缘、任务行左边缘 / 宽度、阶段分组头宽度四组量在「打开前 → 打开后 → 关闭后」全程一致（修复前是 1435 → 1450 → 1435）；
  ③ **不引入新副作用** —— 抽屉面板仍贴视口右边（`position: fixed` 按视口定位，不吃 body 内边距）；关闭后页面照常能滚；
  ④ **可重复** —— 第二次开关的断言与第一次一致（还原干净、没有残留内联样式）。
- 复现条件留档：**页面必须高过视口**（有纵向滚动条）才复现得出来（`sb = innerWidth - documentElement.clientWidth = 15px`）；
  夹具特意做 12 条任务把页面撑高。macOS 悬浮滚动条 / 内容装得下的页面量出来 `sb = 0`，补内边距这一步自动跳过（行为与修复前一致）。
