# ADR-028 时区口径：业务统一 Asia/Shanghai，日界应用层计算 + ClockService 注入

- 状态：草案（Proposed）｜评审：lan、px｜随 PR 合并 main 后转「已采纳（Accepted）」
- 日期：2026-09-20｜决策人：wmj（技术负责人）
- 依据：技术设计v0.3-实施与验收.md §7#13、§3.2 / §3.3；技术设计v0.2-架构与数据模型.md §2.3 / §6.2；系统功能书.md A1-05 / A1-06 / D5-01 ~ D5-03

## 背景

「今天 / 本周 / 逾期 / T-1 / 日界」贯穿首页快筛、时间区间过滤（A1）、逾期派生（A14）、规则提醒与调度（R03~R07、A03）。服务器与数据库可能运行在 UTC，浏览器本地时区也不可控；若各处各算一套，跨日边界必然产生不一致（例如「今天到期」在不同入口取到不同任务）。

## 决策

- **业务统一时区 = Asia/Shanghai**（UTC+8，无夏令时）：今天 / 本周（周一至周日）/ 本月 / 逾期 / T±N / 日界一律按该时区计算。
- **存储不变**：瞬时时间用 timestamptz（UTC）；业务日字段（planned_start / planned_end / actual_end / due 类业务日）按字面日期比较，不做时区换算。
- **计算位置**：日界在应用层按 Asia/Shanghai 算出后以参数进入 SQL；**不依赖数据库会话时区与服务器本地时区**；迁移与运维脚本需要展示时间时显式 set time zone。
- **ClockService 注入**：业务与规则代码禁止直接取系统时间（置位 ADR-025、SLA ADR-026、提醒窗口、逾期派生全部走 ClockService），支持测试固定时钟与金标回放。
- **调度口径**：cron 按 Asia/Shanghai 解释（00:05 置位、08:00 / 09:00 提醒窗口等）；部署环境为 UTC 时不改变行为。
- **展示**：接口下发 ISO 8601（带偏移）；前端按 Asia/Shanghai 展示（一期不做多时区本地化）；「本周」与 A1-05 快筛口径一致（周一为首日）。

## 备选与不采用原因

- 全链路 UTC 口径：业务全部按国内日期填表与沟通，跨日会错，不采用。
- 跟随服务器 / 数据库本地时区：部署环境漂移、不可复现，不采用。
- 按用户浏览器时区：同一数据不同人看到不同「今天」，且一期用户全在国内，不采用。

## 影响与后果

- 所有日界计算收敛到单一 TimeService（含周 / 月口径），filter[timeFrom] / filter[timeTo] 与逾期派生（A14）复用同一实现。
- 测试固定时钟后，R03~R07 金标回放与置位用例可复现（M5 出口标准）。
- D5 工作日历（节假日 / 顺延）以该时区为准；跨时区部署（如海外节点）不改口径。

## 切换触发条件

启用海外项目并需要按项目时区解释「今天 / 逾期」时，新增项目级时区字段并在 TimeService 内按项目解析。
